# 异构多域分布式训练：同域形成 batch，共享知识跨域汇聚

原版概念答疑：[[tactile-vla-qa2.html|触觉 VLA 深度答疑（二）HTML]]  
论文实例：[[FTP-1]] · 相关：[[Morphology-Aware Tactile Token Space]]

> [!summary] 一句话定义
> 当不同数据域使用不同输入格式和专属模块时，把同域样本组成每张 GPU 的 homogeneous batch；专属模块只吸收本域梯度，共享 backbone 汇聚所有域的梯度。

## 第一层：为什么普通随机混合 batch 很麻烦？

假设三个样本分别是：

```text
GelSight image   [B, 224, 224, 3] → sensor-specific ViT
Contactile array [B, H, W, D]     → CNN
Wrist F/T state  [B, 6]           → Fourier + MLP
```

若同一 GPU batch 混入三种 shape，每个样本要动态走不同 module。可以 padding、逐样本分支或先分桶，但会降低向量化效率并让分布式参数同步更复杂。FTP-1 的选择是：**全局 batch 可以多域，本地 GPU batch 保持单域。**

## 第二层：一个可核对的 toy 调度

```python
class DomainAwareTrainer:
    def train_step(self, rank, global_step):
        domain = scheduler.domain_for(rank, global_step)
        batch = loaders[domain].next()      # 此 rank 内 shape 一致

        local = model.sensor_encoders[domain](batch.tactile)
        shared_out = model.shared_modules(local, batch.rgb, batch.action)
        loss = objective(shared_out, batch)
        loss.backward()

        # 逻辑语义：专属参数只根据本域更新；共享参数吸收所有域
        sync_with_domain_peers(model.sensor_encoders[domain].grad)
        sync_across_participating_ranks(model.shared_modules.grad)
        optimizer.step()
```

允许路径：GelSight 数据更新 GelSight encoder，同时也给 shared Tactile/Action Expert 提供梯度。  
禁止路径：GelSight 样本不应更新 Contactile encoder，因为该前端没有参与当前 forward。

### 梯度为什么要分两种范围？

设 shared 参数为 `θ_s`，域 `k` 的专属参数为 `θ_k`：

$$\nabla_{\theta_s}L=\sum_k w_k\nabla_{\theta_s}L_k,\qquad
\nabla_{\theta_k}L=w_k\nabla_{\theta_k}L_k.$$

第一式需要跨域汇聚，第二式只来自本域。真正实现可使用 process groups、conditional modules、FSDP/DDP hook 或其他调度；论文没有公开足够细节来确认是哪一种。

## 第三层：采样比例与 GPU 数不是一回事

FTP-1 Table 4 的 `Sample-Scale` 是为 26 个数据源做 resampling，最终让人类 / 灵巧手 / gripper 数据约为 `20% / 30% / 50%`。实际域权重可以由多种因素共同决定：

```python
effective_weight = (
    assigned_rank_fraction
    * local_batch_size
    * gradient_accumulation_frequency
    * dataset_resampling_probability
)
```

因此不能仅凭“某域分到 6 张 GPU、另一域 4 张”断言最终采样比为 1.5；还要知道 batch、轮转和重采样策略。

## 第四层：FTP-1 论文究竟公开了什么？

### 已核对事实

- 预训练使用 `48 NVIDIA H20 GPUs`、`50k steps`、global batch `768`；
- infrastructure 自动把不同 domain 的数据分到不同 GPU，使单 GPU batch 格式一致；
- domain-specific modules 的梯度独立更新；shared modules 的梯度合并后联合更新；
- Table 4 给出各数据源的 Sample-Scale 与最终比例。

### HTML 中有帮助但属于示意的部分

- “GPU 0–5=GelSight、GPU 12–15=ATI”等 rank 号；
- `dist.new_group()` 的具体分组方式；
- 每个专属 module 是否只物理存在于对应 GPU；
- 精确的 all-reduce 顺序和 optimizer ownership。

这些都是合理实现方案，但不是论文已公开事实。复现前应查看官方训练代码；若代码未开放，则需自己决定 DDP/FSDP 下 unused parameters、optimizer state 和负载均衡怎样处理。

## 工程风险与验证清单

- 小数据域是否频繁重复，导致过拟合？
- shared gradient 是否被大域主导？
- 不同域 step time 差异是否造成同步空等？
- conditional modules 在 DDP/FSDP 中是否触发 unused-parameter 问题？
- checkpoint 是否完整保存所有域 encoder 与 optimizer states？
- 新增传感器时，模型路由、采样权重和评估是否同步更新？
