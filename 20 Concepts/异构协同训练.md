# 异构协同训练：让不同数据补不同能力轴

出现于：[[π₀.5]] · 对比：[[数据策略对比]] · [[异构多域分布式训练]]

> [!summary] 一句话定义
> 异构协同训练不是把所有数据强行变成同一种内容，而是用共享输入/输出接口和参数系统同时学习多种监督，使动作、环境、语义和高层决策各自补足另一类数据的盲区。

## 直觉理解

机器人数据像“实操课”：动作标签精确，但物体、房间和语言覆盖窄；网页视觉语言数据像“百科课”：见识广，却不会控制电机；高层子任务数据像“项目管理课”：告诉系统此刻该完成哪一步。

只有百科课，机器人不会动；只有实操课，换个陌生物体可能认不出。co-training 的目标是让这些课共享同一个学生，而不是假定每门课都直接监督 action。

## 为什么需要统一接口？

π₀.5 第一阶段把 caption、VQA、bbox、subtask 与 FAST action 都写成 token prediction：

```python
def cotrain_step(sample):
    prefix = encode(sample.images, sample.prompt, sample.tokenized_state)

    if sample.kind in {"caption", "vqa", "bbox", "subtask"}:
        target = sample.text_tokens
    elif sample.kind == "robot_action":
        target = FAST.encode(sample.action_chunk)

    return cross_entropy(vlm(prefix), target)
```

共享接口的意义不是所有任务语义相同，而是它们都能更新视觉语言 backbone 与序列建模能力。

## π₀.5 六类数据的职责

| 数据 | 主要覆盖轴 | 不该夸大的地方 |
|---|---|---|
| MM | 目标移动机器人、真实多家庭长任务 | 约 400 小时并不自动等于开放世界 |
| ME | 环境变化与非移动机器人操作 | 与目标 embodiment 有差异 |
| CE | 跨 embodiment 与实验室技能 | 实验室分布不等于真实家庭 |
| HL | bbox + 当前子任务 | 标注合理不等于低层可执行 |
| WD | 开放词汇、VQA、定位 | 没有直接动作监督 |
| VI | 人类给低层 policy 的可执行子任务序列 | 规模小、采集仍需人 |

## 如何判断是否真的协同，而不是数据碰巧更多？

最低限度要做：

1. 单独移除每个来源；
2. 按能力轴报告，而不只看一个总分；
3. 控制训练步数或 unique samples；
4. 区分未见环境、未见物体类别和未见任务；
5. 比较“更多目标数据”和“更多异构数据”。

π₀.5 的结果显示 ME/CE 对总体操作重要，WD 对 OOD 语言跟随和高层推理更明显，说明不同数据确实作用于不同瓶颈。

## 和“异构多域分布式训练”不是一回事

- **异构协同训练**问：哪些数据、任务和 loss 一起训练，知识怎样迁移；
- **异构多域分布式训练**问：这些数据与传感器怎样在工程上分桶、采样、并行计算。

前者是学习策略，后者是训练系统。一个项目可能同时需要两者，但不能互相替代。

## 优势与边界

**优势：** 用非目标数据扩大语义和技能覆盖；共享表示减少重复建模；对昂贵目标机器人数据更节省。

**边界：** 数据比例会造成梯度竞争；标签粒度可能冲突；共享 token 接口不保证知识自动迁移到 Action Expert；必须靠能力分解消融验证。
