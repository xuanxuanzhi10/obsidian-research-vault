# 非阻塞控制与推理延迟：慢模型会改变系统动力学

出现于：[[OpenVLA]] · 相关：[[部署与推理优化]] · [[Action Chunking]]

> [!summary] 一句话定义
> 非阻塞控制中，机器人在等待新预测时继续执行旧动作；因此推理延迟不仅降低吞吐，还会改变动作保持时间和闭环动力学。

## 第一层：直觉入口

模型像导航员，机器人像不会自动停车的司机。导航员思考 200ms 与 800ms 的区别，不只是少给几条建议：司机会把上一条“继续左转”执行四倍时间。

## 第二层：最小时间例子

```python
def non_blocking_loop():
    action = zeros()
    while True:
        robot.keep_executing(action)       # 模型计算期间不会停
        future = async_predict(camera())
        if future.ready():
            action = future.result()

def blocking_loop():
    while True:
        action = predict(camera())         # 等模型
        robot.execute_and_wait(action)     # 完成后才预测下一步
```

若 demonstrations 以 5Hz 采集，每个 action 约保持 200ms；部署只有 1.2Hz 时，旧 action 可能保持约 833ms，输入状态分布随之改变。

## 第三层：与模型精度怎样解耦？

OpenVLA 的 int8 在非阻塞真机上较差，但 blocking control 下 bf16/int8/int4 误差条重叠。这说明主要差异来自 kernel throughput 与时序，而不是 int8 数值表示本身。

| 问题 | 离线 token accuracy | 非阻塞 rollout | blocking rollout |
|---|---|---|---|
| 权重量化误差 | 能观察 | 与延迟混在一起 | 更容易隔离 |
| 动作保持时间 | 看不到 | 直接改变 | 被统一 |
| 真实闭环稳定性 | 看不到 | 能测 | 但不是实际高速运行方式 |

## 第四层：研究核查

- 同时报告 model latency、control tick、action age 与 missed deadline；
- 在相同 wall-clock action hold 下比较模型质量；
- 评测 jitter，而不只平均 Hz；
- 慢模型可用 [[Action Chunking]]、异步 replanning 或低层 servo 解耦，但会引入 open-loop 风险；
- 量化“精度不降”不能只看离线 loss，也不能只看未匹配时序的真机 success。
