# 异步触觉动作细化

> [!summary] 一句话定义
> 让慢速大模型先生成稳定的全局动作先验，再由快速小模型用最新触觉频繁改写未来动作，从而兼得语义规划和接触闭环。

## 直觉理解

像人拿杯子：眼睛和语言决定“拿起并倒水”，指尖在杯子将滑时立即加力。你不会等待大脑重新理解整张场景才做微调。异步结构把这两类反应映射为不同 expert 和不同更新频率。

## 为什么要在同一条 Flow Matching 轨迹上接力？

若快 expert 独立预测残差，它要自己学会“什么是合理动作”和“该修多少”。T-Rex 让慢 expert 从噪声走到 `x̂₀.₄`，快 expert只完成 `.4→0`，因此触觉是在已有视觉动作流形附近细化，而不是从头规划。

```python
class SlowFastFlowController:
    def plan(self, vision_language):
        x = randn([16, 62])
        for tau in [1., .9, .8, .7, .6, .5]:
            x -= .1 * action_expert(x, tau, vision_language)
        cache.commit(x_boundary=x, kv=reencode_context_and_action(x))

    def react(self, tactile):
        x, kv = cache.snapshot()
        for tau in [.4, .3, .2, .1]:
            x -= .1 * tactile_expert(x, tau, tactile, kv)
        return x
```

## 系统层真正困难的地方

- **频率解耦**：慢规划约 5 Hz，快触觉约 20 Hz，底层控制 300 Hz；三者不是同一个 loop。
- **缓存一致性**：`KV_lat` 与 `KV_act@boundary` 必须属于同一次慢 tick。
- **线程安全**：缓存提交与读取要串行化，否则会产生混合状态。
- **模态陈旧**：视觉缓存会比实时触觉旧；训练需用 delay augmentation 模拟。
- **动作替换**：fast tick 只能替换尚未执行的 action chunk 部分。

## 与相邻概念区分

- [[Action Chunking]] 解决“一次预测多步”；异步细化解决“执行中如何重写未来多步”。
- [[KV Cache]] 提供复用机制；异步控制决定谁在什么频率消费缓存。
- 普通 residual policy 在动作空间加修正；T-Rex 在生成轨迹的后半段完成去噪。
- [[Block-wise Causal Attention]] 管信息可见性；异步细化还管真实时间中的更新调度。

## 证据与局限

T-Rex 六任务平均从无异步 60% 提升到 65%，表明调度设计有额外收益；但更大的差距来自是否使用触觉（42%→65%）。论文未报告端到端 latency、GPU 占用或 deadline miss rate，所以“更快”的系统收益仍需工程基准补足。
