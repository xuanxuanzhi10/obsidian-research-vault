> [!summary] 一句话结论
> π₀.5 用大规模异构数据先把图像、语言、高层子任务和离散动作统一成 next-token prediction，再在后训练阶段加入连续 Flow Action Expert；推理时，同一模型先说出当前可执行的子任务，再以它为条件生成低层 action chunk，从而把开放世界语义泛化接到真实机器人控制上。

## 00 先建立问题链：这篇论文到底在解决什么？

读 π₀.5 不要从模块名开始，而要沿着四个失败逐步往下问：

```text
失败 1：机器人会动作，但只在熟悉场景和熟悉物体上可靠
→ 需要互联网视觉语言知识与更多环境覆盖

失败 2：网页数据懂世界，却没有机器人 action label
→ 需要一个能容纳不同输出类型的统一训练接口

失败 3：离散 action token 适合大规模 next-token 预训练，
        但自回归生成整段高频动作太慢、太粗
→ 预训练用 FAST，后训练补一个连续 Flow Action Expert

失败 4：“整理卧室”横跨很多分钟，直接映射到下一段关节动作太远
→ 同一模型先预测局部语义子任务，再据此生成低层动作
```

因此，这篇论文不是简单地说“π₀ 加了更多数据”。它同时修改了：

1. **数据的覆盖轴**：机器人、环境、形态、网页语义、高层标注、口头指令；
2. **训练接口**：离散预训练 + 连续后训练；
3. **推理分解**：总任务 → 当前子任务 → action chunk；
4. **状态与时间条件路径**：state 进入 tokenized prefix，flow timestep 逐层调制 Action Expert。

## 01 先看论文原始 pipeline

![[90 Attachments/Pi05/pi05-fig3-pipeline.png]]

*论文 Figure 3（PDF 第 4 页）原图裁剪。左边是预训练，右边是后训练与推理。*

### 读图时要抓住三条线

**第一条：预训练输出全部离散化。** 语言子任务、caption、bbox 本来就是 token；机器人连续动作先用 [[FAST Tokenizer]] 压成离散 action tokens。于是它们都能使用标准交叉熵训练 VLM。

**第二条：后训练才加入 Action Expert。** 新的 300M expert 接收噪声 action chunk，用 Flow Matching 生成连续动作；文本头仍然负责高层子任务。

**第三条：推理时有明确条件依赖。** 模型先从“clean the bedroom”生成“pick up the pillow”，低层动作随后以这个预测子任务为条件。

> [!question] 为什么论文叫同一个模型，却又有 VLM 和 Action Expert？
> “同一个模型”指共享同一前缀表示、同一套 joint-attention 计算图和统一训练目标，并非所有 token 必须走相同 FFN 参数。VLM 负责视觉语言与文本输出；较小的 Action Expert 专门处理连续动作 token。可把它理解为一个系统内的两个 expert，而不是先调用一个独立 planner，再把字符串发给完全分离的 policy。

## 02 核心机制一：离散预训练，连续后训练

![[90 Attachments/Pi05/pi05-teaching-training.svg]]

*教学图，按 Sec. IV 与训练配置整理，并非论文原图。*

### 2.1 为什么不从头到尾只用 Flow Matching？

Flow Matching 对连续动作很自然，但每个机器人样本需要额外的 noisy action、timestep 和向量场回归；异构网页任务又没有动作。反过来，离散 token 可以把 caption、VQA、bbox、subtask 和 FAST action 都写成同一种“预测下一个 token”的问题，直接复用成熟的 VLM 训练基础设施。

这带来一条实际因果链：

```text
连续动作用 FAST 压缩成少量 token
→ robot batch 与 web / language batch 共用 autoregressive CE
→ 第一阶段可以稳定、便宜地吸收大量异构数据
→ 再用连续 expert 恢复实时控制所需的精度与并行生成
```

### 2.2 两阶段目标到底是什么？

论文的联合目标可以概括为：

$$
\mathcal L = \mathcal L_{CE}(\text{text and FAST tokens})
+ \alpha\,\mathcal L_{flow}(\text{continuous action field}).
$$

```python
def pretrain(batch):
    # 280k steps；包括机器人与非机器人任务
    # 连续动作先经 FAST，所有监督统一成离散 token
    target_tokens = encode_text_bbox_subtask_or_fast_action(batch)
    logits = vlm(batch.images, batch.prompt, batch.tokenized_state)
    loss = cross_entropy(logits, target_tokens)   # alpha = 0
    update(vlm, loss)

def posttrain(batch):
    # 80k steps；加入新初始化的 300M Action Expert
    text_loss = next_token_loss(batch)
    flow_loss = flow_vector_field_loss(batch.continuous_action)
    loss = text_loss + 10.0 * flow_loss           # alpha = 10
    update(vlm_and_action_expert, loss)
```

这是教学伪代码，用来显示监督接口，不是官方逐行实现。

> [!question] 后训练是否把 FAST 丢掉了？
> 不能这样理解。论文的联合目标仍包含离散 token 分支，并用注意力掩码隔离 FAST action tokens 与 Flow Action Expert embeddings；实际机器人推理则使用文本自回归 + 连续 Flow Action Expert，而不是自回归解码整段 FAST 动作。

> [!question] 为什么连续 expert 要在第二阶段新初始化，不会破坏预训练知识吗？
> Action Expert 从共享的视觉、语言和 state prefix 读取条件；预训练 VLM 已经学到场景、任务和粗动作关系。新 expert 的任务是把这些条件“翻译”为连续向量场。论文报告该流程训练稳定，但没有给“随机初始化 vs 其他初始化”的独立消融，所以不能把收益全部归因于初始化策略。

## 03 核心机制二：同一模型做高层与低层推理

论文把联合分布明确分解为：

$$
\pi_\theta(a_{t:t+H},\hat\ell\mid o_t,\ell)
=\pi_\theta(a_{t:t+H}\mid o_t,\hat\ell)\,
 \pi_\theta(\hat\ell\mid o_t,\ell).
$$

- $\ell$：总任务，例如“把碗碟收好”；
- $\hat\ell$：模型当前预测的子任务，例如“拿起盘子”；
- $o_t=[I_t^1,\ldots,I_t^n,q_t]$：图像与机器人本体状态；
- $a_{t:t+H}$：连续 action chunk。

最容易漏掉的一点是：**低层动作分布依赖预测子任务 $\hat\ell$，论文在这个分解中不再让它直接依赖原始总任务 $\ell$。**

![[90 Attachments/Pi05/pi05-teaching-inference.svg]]

*教学图：突出推理顺序和条件依赖，并非论文原图。*

```python
def pi05_control_step(images, proprio, long_horizon_command):
    state_tokens = discretize_as_text(proprio)
    prefix = encode(images, long_horizon_command, state_tokens)

    # 第一次使用同一 VLA：生成机器人当前能执行的语义子任务
    subtask = autoregressive_text_decode(prefix)

    # 第二次使用同一 VLA：subtask 变成低层命令
    action = gaussian_noise(shape=[50, action_dim])
    for tau in flow_schedule(num_steps=10):
        velocity = action_expert(prefix, subtask, action, tau)
        action = euler_update(action, velocity, tau)

    execute_part_of_chunk(action)
    return observe_again()
```

论文索引写 `H=49`，指 `t:t+H` 包含 **50 个动作位置**；因此不要把它误读成只有 49 个动作。

### 为什么这个子任务不是装饰性 CoT？

因为它进入低层 policy 的条件。如果高层说“pick up pillow”，低层看到的是一个比“clean bedroom”更短、更接近当前可见物体和当前动作的目标。它减少了长任务与瞬时控制之间的语义距离。

但它也不是完整的符号规划器：论文没有维护显式世界状态、任务树或保证无循环的 planner。高层预测仍可能分心、重复开关抽屉。

## 04 核心机制三：六类数据各自补哪个洞？

![[90 Attachments/Pi05/pi05-teaching-data.svg]]

*教学图：根据 Sec. IV-C/D 的数据定义和消融结果整理，并非论文原图。*

### 4.1 预训练的五类来源

| 缩写 | 数据是什么 | 直接监督 | 主要补的能力缺口 |
|---|---|---|---|
| MM | 多环境移动双臂操作，约 400 小时、约 100 个真实家庭环境 | FAST action、部分高层标签 | 目标机器人形态与长任务落地 |
| ME | 多环境非移动单/双臂数据 | robot action | 环境变化与通用操作经验 |
| CE | 实验室跨 embodiment 数据，含扩展 OXE | robot action | 技能与机器人形态覆盖 |
| HL | 多阶段 MM/ME/CE 轨迹的人工子任务与相关 bbox | bbox + subtask text | 从当前观察推断“下一步做什么” |
| WD | caption、VQA、object localization 等网页多模态数据 | text / bbox | 开放词汇、陌生物体和常识语义 |

### 4.2 后训练又做了什么筛选？

- 使用 MM 与 ME，但筛选为成功且短于固定最大时长的 episodes；
- 保留 WD；
- 使用适合多环境任务的 HL 子集；
- 新增 **VI（verbal instruction）**：人类通过实时给低层 policy 下子任务命令来“遥操作”它；
- 省略实验室 CE，使后训练聚焦移动操作和多环境任务。

### 4.3 VI 为什么只有约 11%，却很关键？

HL 标注告诉模型“这里可以说什么子任务”；VI 更进一步记录了：**为了让现有低层 policy 真正完成长任务，人类在什么时刻会下什么命令。** 它把高层语言分布对齐到机器人的可执行能力。

论文的 `no VI` 消融明显下降，说明高层策略不仅要语言合理，还要“懂得怎样指挥这个低层 policy”。但这里仍是相关的训练消融，不能推出 11% 是普遍最优配比。

### 4.4 动作空间如何统一？

```python
def standardize_action(raw_action, dataset_stats, control_mode):
    # prompt 明示 joint 或 end-effector control mode
    lo = dataset_stats.quantile_01
    hi = dataset_stats.quantile_99
    action = 2 * (raw_action - lo) / (hi - lo) - 1
    action = clip(action, -1, 1)
    return zero_pad_to_shared_dimension(action)
```

论文对不同数据集的每个 action 维度使用 1%/99% 分位数归一化到 `[-1,1]`，低维动作空间补零；同时训练目标 joint pose 与 end-effector pose，并在文本 prompt 中写明 control mode。

> [!question] WD 没有 action，怎么可能帮助最终动作？
> 它不会直接告诉机器人电机怎么转。允许的因果链是：WD 改善开放词汇识别、定位和指令理解 → 高层选对对象和子任务的概率提高 → 低层 policy 获得更正确的条件。Figure 11/13 支持它对 OOD 语言跟随和高层策略有帮助；Figure 10 的四项总体操作分数中，`no WD` 与完整模型差异并不显著，因此不能笼统说 WD 提升所有 motor skill。

## 05 模型内部：哪些 token 能看见谁？

![[90 Attachments/Pi05/pi05-fig18-mask.png]]

*论文 Figure 18（Appendix E，PDF 第 19 页）原图裁剪；深色表示允许 attention。*

### 5.1 三组计算角色

1. **Prefix**：images、prompt、tokenized proprioceptive state，组内双向可见；
2. **FAST action tokens**：看 prefix，并以自回归因果方式看此前 FAST tokens；
3. **Flow Action Expert embeddings**：看 prefix，也能在 action chunk 内互看。

关键隔离是：Flow action embeddings **不看 FAST action tokens**。否则 Flow 分支训练时可能偷看由同一真实 action 编码出的离散答案，产生信息泄漏。

```python
def pi05_attention_mask(query_group, key_group, i=None, j=None):
    if query_group == "prefix":
        return key_group == "prefix"

    if query_group == "fast_action":
        if key_group == "prefix": return True
        if key_group == "fast_action": return j <= i
        return False                    # 不能看 flow action

    if query_group == "flow_action":
        if key_group == "prefix": return True
        if key_group == "flow_action": return True
        return False                    # 不能偷看 FAST action answer
```

信息方向总体上是 `VLM prefix → Action Expert`；VLM embeddings 不反向读取 Action Expert。

> [!question] 这和 π₀ 的 block-wise causal mask 完全一样吗？
> 不是。思想都在保护可缓存前缀并限制信息流，但 π₀ 的主要分组是 perception `P`、continuous state `S`、noisy action `A`；π₀.5 还要同时容纳 tokenized state、FAST action tokens 和 Flow Action Expert，因此掩码服务于“离散/连续双动作表示隔离”。

## 06 State、timestep 与 Adaptive RMSNorm：最容易被说错的部分

### 6.1 π₀.5 的 state 去哪里？

机器人 state $q_t$ 包括关节角、gripper pose、torso lift pose 与 base velocity。论文明确说它被**离散化并作为文本 token 输入 prefix**。所以：

```text
proprio state → discretize/tokenize → prefix self-attention
```

它不是 Appendix E 所述 AdaRMSNorm 的调制条件。

### 6.2 AdaRMSNorm 接收什么？

接收 **Flow Matching timestep $\tau$**：

```python
def action_expert_inputs(noisy_action, tau):
    action_tokens = linear(noisy_action)

    # π₀.5 与 π₀ 的关键实现差异
    tau_feature = sinusoidal_encoding(tau)
    tau_condition = swish(W2 @ swish(W1 @ tau_feature))

    for layer in action_expert:
        action_tokens = layer(
            action_tokens,
            prefix_kv=vlm_prefix,
            adaptive_rmsnorm_condition=tau_condition,
        )
    return linear_to_vector_field(action_tokens)
```

原始 [[π₀]] 是先把 noisy action 与 timestep feature 融合，再送入 transformer；π₀.5 改为 timestep 专用 MLP + 每层 Adaptive RMSNorm。详细对照见 [[状态条件注入方式比较]]。

> [!danger] 必须纠正的误解
> “π₀.5 用 AdaRMSNorm 注入 state，所以不再有 state token”是错的。正确说法是：**state 是离散 prefix tokens；AdaRMSNorm 调制的是 timestep。**

## 07 机器人与控制接口

- 两种移动双臂平台；每个平台有两个 6-DoF arm、平行夹爪、全向底盘和 torso lift；
- 4 个 RGB camera：前、后、两个 wrist；
- 高层推理使用 4 路相机；低层 policy 使用两个 wrist + forward camera；
- 两个平台 state/action 维数分别为 18 或 19；
- policy 直接输出 arm、gripper、torso 的目标 pose，以及 base velocity；
- 控制频率 50 Hz，并使用 action chunking；
- 低层由简单 PD controller 跟踪，**没有 trajectory planning，也没有 collision detection**。

最后一点是部署安全边界，不能被“端到端”这个优点掩盖。

## 08 实验怎样回答论文的四个核心问题？

### 8.1 环境数量增加，真的带来 open-world generalization 吗？

![[90 Attachments/Pi05/pi05-fig8-scaling.png]]

*论文 Figure 8（PDF 第 9 页）原图裁剪。*

训练位置从 3、12、22、53、82 扩到 104，四个家庭任务的平均进度总体上升。104-location 模型在未见测试家庭中的表现接近“直接用测试家庭数据训练”的 in-domain baseline。

但图中还有更重要的对照：只用 104 个地点的移动操作数据、却不使用完整预训练 recipe 的 baseline 仍明显更差；即使直接看过测试家庭但缺少完整 recipe，也不等于学会广泛泛化。结论是**环境覆盖和异构协同训练共同起作用**，不是“104”这个数字本身有魔法。

### 8.2 哪类数据真的有用？

![[90 Attachments/Pi05/pi05-fig10-data-ablation.png]]

*论文 Figure 10（PDF 第 10 页）原图裁剪。*

- 去掉 ME 或 CE，平均任务进度显著下降；
- 两者都去掉更差，支持跨 embodiment 与跨环境 robot data 的迁移；
- 去掉 WD 在这四项总体指标上差异不显著（图中 `p=0.385`）；
- 但 Figure 11 显示 WD 对 OOD 物体语言跟随更重要。

这正好说明：数据源应按**它补的能力轴**解释，不能只问“总分涨没涨”。

### 8.3 收益只是 π₀ 训练不够久吗？

![[90 Attachments/Pi05/pi05-fig12-model-comparison.png]]

*论文 Figure 12（PDF 第 10 页）原图裁剪。*

比较项：

- `π₀ 80k`：原始连续 Flow Action Expert 路线；
- `π₀ 300k`：把原始 π₀ 训练更久；
- `π₀-FAST+Flow`：也用离散预训练 + Flow 后训练，但只用 robot action data，不做高层推理；
- `π₀.5`：完整异构 co-training + 高层/低层统一推理。

π₀.5 在四项任务上都更强；π₀ 延长到 300k 仍未追平。这支持“FAST 的预训练计算效率 + 数据/高层设计”超出单纯堆训练步数。

> [!danger] HTML 指南中的一处易错表述
> 原始 π₀ **不是**“先用 FAST 预训练”的模型；它从训练到推理都使用连续 Flow Action Expert。`π₀-FAST+Flow` 是 π₀.5 论文为公平比较构造的增强基线。π₀.5 才把 FAST 离散预训练与 Flow 后训练系统组合起来。

### 8.4 高层子任务真的必要吗？

![[90 Attachments/Pi05/pi05-fig13-high-level.png]]

*论文 Figure 13（PDF 第 11 页）原图裁剪。*

| 变体 | 它改变了什么 | 读图结论 |
|---|---|---|
| π₀.5 | 完整显式高层 + 完整数据 | 最好 |
| implicit HL | 训练见过 HL，但运行时不生成子任务 | 第二好 |
| no HL | 训练和运行都没有 HL | 明显下降 |
| no VI | 去掉 verbal-instruction 数据 | 约 11% 的小数据切片却影响很大 |
| no WD | 去掉网页数据 | 高层表现显著下降 |
| GPT-4 HL | 零样本 GPT-4 选常用标签 | 最差 |
| human HL | 人给子任务 oracle | 仍低于完整模型 |

为什么完整模型能超过 human HL？不能解释为“机器规划一定胜过人”。更谨慎的推断是：高层命令是否与低层 policy 的训练分布、粒度和时机匹配，比语言上是否听起来完美更重要；完整模型在 co-training 中共同适配了两层接口。

`implicit HL` 仍很强也很关键：一部分收益来自 HL 数据塑造了共享表示，而不只是运行时多生成一句文本。

## 09 主动回答读者会追问的问题

> [!question] π₀.5 的 97.6% 非目标任务数据是什么意思？
> 论文指出第一阶段 97.6% 的样本不是目标移动家庭操作数据。这说明目标能力并非靠把同类数据占满 batch 得到；但它不表示这些样本与家庭语义完全无关，也不表示 2.4% 是所有项目的最优比例。

> [!question] “未见家庭”是否等于“任务也完全没见过”？
> 不等于。主要主张是环境与具体实例未见；训练中存在语义相关的家务技能和高层标注。论文另有 OOD object-category 的语言跟随测试，用来更直接测试未见类别。应分别说清场景泛化、物体类别泛化与任务组合泛化。

> [!question] 展示视频说 10–15 分钟，实验为什么又写 2–5 分钟？
> 它们指不同层面的证据：论文展示系统可执行约 10–15 分钟的长时程案例；定量评测中的单次任务常为 2–5 分钟，并按 rubric 统计 task progress。不能把最长 demo 时长当成所有实验 episode 的长度。

> [!question] 同一模型预测高层和低层，是否真的比两个模型好？
> 论文显示完整 π₀.5 优于外部 GPT-4 高层和 human HL，但没有在完全同预算、完全同训练数据下系统比较所有“双模型 planner + policy”架构。因此证据支持联合适配很重要，不足以证明所有模块化方案都更差。

> [!question] Flow Matching 的训练方向到底是什么？
> 论文写插值 $a^{\tau,\omega}=\tau a+(1-\tau)\omega$，按数学求导应对应 $a-\omega$；但正文与 Eq. (1) 排版写成预测 $\omega-a$。这与从噪声积分到数据的常见方向及 π₀ 记号不一致。复现时应以官方实现的积分方向为准，当前笔记把它标为**符号警报**，不擅自改写成确定结论。

> [!question] 10 次 flow 去噪是否意味着输出 10 个动作？
> 不是。10 是整个 action chunk 的积分/网络评估次数；每次都更新同一个 `[50, action_dim]` 候选块，最终一次得到 50 个动作位置。

## 10 局限、失败模式与安全边界

论文主动报告的限制包括：

- 陌生把手、物理上难开的柜门仍会失败；
- 手臂遮挡泼洒区域等 partial observability 问题；
- 高层子任务可能分心，重复开关抽屉；
- prompt 仍较简单，复杂偏好与约束需要更丰富标注；
- context/memory 较弱，跨房间导航或记住物体位置仍困难；
- 只探索了特定异构数据组合，不能视为完整配方搜索；
- 直接 50 Hz 端到端控制，没有 trajectory planner 和 collision detection。

```text
当前成功边界：陌生家庭中的已覆盖家务技能组合
仍未解决：持久记忆 + 强部分可观测性 + 安全约束 + 真正开放任务集合
```

## 11 和 π₀ 的最小差异表

| 维度 | [[π₀]] | π₀.5 |
|---|---|---|
| 研究问题 | 通用 VLM 怎样生成高频灵巧连续动作 | 怎样在未见家庭完成开放世界长任务 |
| 第一阶段动作 | 直接 Flow Matching Action Expert | FAST 离散 action tokens |
| 后训练 | 任务专项高质量数据 | 文本 CE + 连续 Flow Expert，聚焦移动多环境 |
| 高层子任务 | 不作为核心推理阶段 | 同一模型显式预测 $\hat\ell$ |
| state | continuous state suffix block | 离散化后进入 text-token prefix |
| timestep | 与 noisy action embedding 融合 | timestep MLP → 每层 AdaRMSNorm |
| 数据 | 大规模跨 embodiment robot data + VLM prior | MM/ME/CE/HL/WD，后训练再加 VI |
| action horizon | 50 | 50（索引记 H=49） |
| flow inference | 10 Euler steps | 10 denoising/integration steps |

两者的尺寸基本沿用同一坐标：PaliGemma VLM 约 2.6B（SigLIP 约 400M + Gemma 约 2B），Action Expert 约 300M；VLM width 2048/depth 18，Action Expert width 1024/MLP 4096。

## 12 如果我要复现或迁移，先做什么？

```python
reproduction_checklist = [
    "明确每个 dataset 的 control mode 与 action 维度",
    "按数据集统计 1%/99% quantile，而不是混成一份全局统计",
    "验证 FAST token 与 flow token 的 attention 隔离",
    "确认 state 进入 tokenized prefix，tau 才进入 AdaRMSNorm",
    "预训练 alpha=0；后训练加入新 Action Expert 与 alpha=10",
    "分别报告场景泛化、OOD object language following、motor success",
    "长任务除最终成功外，还要按 rubric 报 task progress",
    "部署补碰撞检测、限速与 emergency stop",
]
```

如果迁移到新的机器人，最危险的不是改视觉 backbone，而是 action normalization、control mode、state 序列化和高层命令粒度错位。它们一旦和训练数据定义不一致，模型可能语义上“知道该做什么”，但低层接口无法执行。

## 13 证据边界与我的判断

### 论文直接支持

- 两阶段离散/连续训练与具体 280k、80k、`α=10` 配置；
- MM/ME/CE/HL/WD/VI 的定义及多组消融；
- state tokenization、timestep AdaRMSNorm、50-action horizon、10-step flow inference；
- 在未见家庭中的定量/定性结果与主要失败模式。

### 合理机制解释，但不是论文的独立证明

- FAST 的主要价值可解释为统一接口与预训练计算效率；
- VI 让高层语言粒度贴合低层 policy 的可执行分布；
- 同一模型减少 planner-policy interface mismatch。

这些解释与论文设计和消融一致，但没有全部由一对一机制实验隔离。

### 仍需官方代码或后续论文确认

- Eq. (1) 中 flow vector field 的符号方向；
- 每种数据精确配比与采样策略的普遍最优性；
- 与完全同预算的模块化 planner + policy 的公平比较；
- 没有 collision detection 时的系统化安全统计。

## 14 复习卡片

> [!tip] 只记五句话
> 1. π₀.5 的目标是 **open-world generalization**，不是只把单项 manipulation 做得更准。<br>
> 2. **预训练 FAST、后训练 Flow**：先统一异构监督，再恢复连续实时控制。<br>
> 3. **总任务 → 子任务 → action**，同一模型承担高层与低层。<br>
> 4. **state 是 tokenized prefix；AdaRMSNorm 注入的是 timestep。**<br>
> 5. 泛化来自环境规模与 co-training recipe 的共同作用，不能缩写成“400 小时移动数据”。
