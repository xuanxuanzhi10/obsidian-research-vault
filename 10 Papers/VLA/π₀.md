# π₀：让 VLM 保留语义能力，让 Action Expert 学会连续控制

上级地图：[[VLA 学习地图]] · 对比：[[VLA 方法比较]]

核心概念：[[Action Expert]] · [[Flow Matching]] · [[Block-wise Causal Attention]] · [[KV Cache]] · [[Action Chunking]]

原文：[[pi0.pdf|论文 PDF]] · [[pi0-study-guide.html|Claude HTML 原版讲解（系统浏览器打开）]] · [项目页](https://www.physicalintelligence.company/blog/pi0)

> [!abstract] 一句话结论
> π₀ 用预训练 PaliGemma 负责看懂图像和指令，用约 300M 的 Action Expert 专门处理 robot state 与连续动作；二者只在 joint attention 中交流，再用 Flow Matching 一次生成 H=50 的高频 action chunk。它真正提出的是“语义预训练 + 专用连续控制 + 大规模跨机器人数据 + 高质量 post-training”的完整配方。

## 先看原论文 pipeline

> [!info] Figure 3 · PDF 第 4 页 · 原论文图片

![[pi0-fig3-framework.png]]

### 看图顺序

1. 左侧三类知识来源：π 团队的跨机器人数据、Internet-pretrained VLM、开放 OXE robot data；
2. 中间蓝色 VLM 路径接收 2–3 张 RGB 与语言，绿色 Action Expert 接收 robot state `q_t` 和 noisy action tokens；
3. 两路不是先后运行的硬流水线，而是在 18 层 Transformer 的每层 joint attention 中交换信息；
4. 顶部从 noisy actions 经十步速度场积分，联合输出 `a_t … a_{t+H-1}`；
5. 右侧不同机器人共用一套 3.3B 权重，但各自 action/configuration space 先 pad 到 18 维。

```text
images + language ──PaliGemma expert──────┐
                                         ├─ joint self-attention × 18
state q_t ─────────Action Expert─────────┤
noisy action A^τ ──Action Expert─────────┘
                      ↓ 预测整块速度 vθ[A^τ]
                  Euler 积分 10 次
                      ↓
                  H=50 连续动作
```

## 为什么“把机器人动作当成文本 token”在这里不够？

早期 VLA（如 [[OpenVLA]]）把动作离散化后自回归输出。这对低频、短动作有工程优势，但 π₀ 面对的是折衣服、装箱、拿薄玻璃杯等高频灵巧任务：

```text
若 50 个时间步 × D 个动作维度依次生成
→ 解码延迟随 token 数串行增加
→ 每一步只能看到此前动作，不能同时协调整条轨迹
→ 量化还会损失毫米级连续精度
```

因此 π₀ 把问题改成：给定 observation，直接学习连续 action chunk 的条件分布 `p(A_t|o_t)`；Action Expert 中 50 个动作 token 双向注意并同时更新。

论文的证据不是“连续一定普遍优于离散”，而是 Figure 7 中 OpenVLA 即使在同一大混合数据上训练仍明显落后；作者把原因归于其自回归离散化不支持 action chunking 和高频控制。但架构、模型容量和训练成熟度也同时不同，不能把差距全归因于动作表示。

## 两个 expert 到底怎样共处在一个 Transformer？

π₀ 受 Transfusion 启发，每层有两套参数：

| Token | Expert | 宽度 / MLP | 初始化 |
|---|---|---|---|
| 图像、语言 | PaliGemma VLM | width 2048 / MLP 16384 | Internet pretrained |
| state、noisy action | Action Expert | width 1024 / MLP 4096 | 从头训练 |

PaliGemma 基于 Gemma 2B，18 层、18 个 query heads、1 个 KV head、head dim 256；Action Expert 沿用 18 层结构但变窄，总计约 300M。加上 VLM 后模型约 3.3B。

两套 width 不同为什么还能注意？因为各 expert 用自己的 Q/K/V projection，把 token 投影到兼容的 attention head 空间；拼接 K/V 后做一次联合注意力，再各自走独立 FFN 与 residual stream。

```python
class Pi0TransformerLayer:
    def forward(self, vl_tokens, robot_tokens, mask):
        # vl_tokens:    [B, N_image+N_text, 2048]
        # robot_tokens: [B, 1+H, 1024]，1 个 state + H=50 actions

        q_v, k_v, v_v = self.vlm_attention.project(vl_tokens)
        q_r, k_r, v_r = self.action_attention.project(robot_tokens)

        # 唯一的跨专家通信位置：同一个 attention 图中读取对方的 K/V
        q = concat_sequence(q_v, q_r)
        k = concat_sequence(k_v, k_r)
        v = concat_sequence(v_v, v_r)
        mixed = masked_attention(q, k, v, mask)

        # 注意力之后重新分流；两套 FFN 参数不共享
        vl_next = self.vlm_ffn(mixed.vlm_slice)
        robot_next = self.action_ffn(mixed.robot_slice)
        return vl_next, robot_next
```

这就是 [[Mixture of Transformers]] 思想的早期清晰实例：专门化的是参数路径，不是像稀疏 MoE 那样由 learned router 给每个 token 动态挑 expert。

## 为什么需要三块 attention mask？

![[pi0-teaching-mask.svg]]

序列被分成：

```text
P = [images, language] | S = [q_t] | A = [a_t^τ ... a_t+49^τ]
```

| Query block | 能读 P | 能读 S | 能读 A |
|---|---:|---:|---:|
| P | ✓（块内双向） | ✗ | ✗ |
| S | ✓ | ✓ | ✗ |
| A | ✓ | ✓ | ✓（块内双向） |

因果链：

- P 不读新增机器人 token，尽量维持 PaliGemma 预训练时的输入结构；
- S 不读 A，所以同一 observation 下 state 表示不会随 flow timestep 改变；
- A 读全部条件，且 50 个 action tokens 互相可见，能协调完整轨迹；
- P 与 S 的隐藏状态/KV 因此可以在十步 solver 中缓存。

> [!warning] 最容易被 HTML 解读带偏的一点
> “感知不读取动作”只约束前向信息流，**不等于 action loss 不会更新 VLM**。Action query 会读取 VLM 的 K/V，所以 flow loss 的梯度可以沿该路径反向进入 PaliGemma。论文说继续训练整个 VLA，也没有描述另加语言 cross-entropy 辅助目标来更新 VLM。

## Flow Matching 到底如何把噪声变成动作？

![[pi0-teaching-flow.svg]]

### 用一个标量例子先跑通

设真实动作 `A=3`，随机噪声 `ε=-1`。论文使用线性路径：

$$A^\tau=\tau A+(1-\tau)\epsilon=-1+4\tau.$$

当 `τ=0.25`，模型看到的中间动作是 0；这条路径真实速度恒为：

$$u(A^\tau|A)=A-\epsilon=4.$$

真实任务中 A、ε、Aτ、v 都是 `[B,H=50,D=18]`。训练算法为：

```python
def pi0_flow_training(batch):
    observation = (batch.images, batch.language, batch.state)
    A = pad_to_18(batch.action_chunk)            # [B, 50, 18]
    eps = randn_like(A)                          # [B, 50, 18]

    # 先 x~Beta(1.5,1)，再 τ=s(1-x)；因此偏向 τ≈0 的高噪声区
    tau = shifted_beta_sample(s=0.999)           # [B,1,1]
    A_tau = tau * A + (1 - tau) * eps

    v_pred = pi0(observation, A_tau, tau)         # [B,50,18]
    v_target = A - eps
    return mean_squared_error(v_pred, v_target)
```

noisy action embedding 不是一层简单线性投影，而是：

$$e(a^\tau)=W_3\,\mathrm{swish}(W_2\,[W_1a^\tau;\phi(\tau)]),$$

其中 `φ(τ)` 是 sinusoidal encoding。论文没有使用 π₀.5/DiT 式 [[Adaptive RMSNorm]] 注入 timestep；τ 在 π₀ 中直接进入 action embedding MLP。

### 为什么 τ 不均匀采样？

论文使用截止点 `s=0.999` 的 shifted Beta 分布，强调低 τ（动作更嘈杂）的区域。作者的解释是：observation 对合理动作的约束很强，因此从高噪声处恢复条件均值仍很难，训练资源应更多投向这里；τ>s 完全不采样，只要推理积分步长 `δ>1-s` 即可覆盖终点。

这是作者提出的假设与经验设计，论文没有单独给出 uniform/logit-normal/shifted-beta 的下游消融，不能称为已被独立证明的最优分布。

## 推理为什么不是“3.3B 模型完整跑十遍”？

![[pi0-teaching-cache.svg]]

```python
def generate_chunk(images, language, state):
    # 固定 observation 只算一次
    prefix_kv = pi0.encode_and_cache(images, language, state)

    A = randn(50, 18)
    for step in range(10):
        tau = step / 10
        # 只重算随 τ 改变的 action suffix
        velocity = pi0.action_suffix(A, tau, prefix_kv)
        A = A + 0.1 * velocity
    return A
```

论文 Appendix D 在 RTX 4090、三路相机上的报告：

| 部分 | 时间 |
|---|---:|
| image encoders | 14 ms |
| observation forward | 32 ms |
| 10× action forward | 27 ms |
| on-board 总计 | 73 ms |
| off-board Wi-Fi 额外网络延迟 | 13 ms |
| off-board 总计 | 86 ms |

不要把“最高 50 Hz 动作控制”理解成每 20 ms 完整推理一次：

- UR5e/Franka 以 20 Hz 执行，每执行 16 步（0.8 s）重新推理；
- 其他机器人以 50 Hz 执行，每执行 25 步（0.5 s）重新推理；
- 每次生成 50 步，但只消费前 16 或 25 步，剩余丢弃，以新 observation 重规划；
- 作者早期尝试 temporal ensembling，发现性能下降，因此采用 open-loop chunk segment，不做跨 chunk 聚合。

这与 [[Hy-Embodied-0.5-VLA]] 的 Bézier 拼接形成直接工程差异：两者都生成 chunk，但如何处理相邻 chunk 不连续并没有统一答案。

## 一个模型如何兼容七类机器人？

论文把机器人配置按运动学类别归成 7 种 configuration，实际包含若干相近硬件：UR5e、双 UR5e、Franka、双 Trossen、双 ARX/AgileX、移动 Trossen/ARX、移动 Fibocom。

| 类别 | cameras | state dim | action dim |
|---|---:|---:|---:|
| UR5e | 2 | 7 | 7 |
| Bimanual UR5e | 3 | 14 | 14 |
| Franka | 2 | 8 | 8 |
| Bimanual Trossen | 3 | 14 | 14 |
| Bimanual ARX / AgileX | 3 | 14 | 14 |
| Mobile Trossen / ARX | 3 | 14 | 16 |
| Mobile Fibocom | 3 | 14 | 17 |

所有 `q_t` 与 action 都 pad 到 18 维，以容纳双 6-DoF 手臂、两个 gripper、mobile base 与可升降 torso；不足三路相机时 mask 掉缺失 image slot。它没有像后来的 HyVLA 那样主打统一 relative-EEF canonical action schema，而是把不同机器人原有坐标表示塞进共享 18D 容器，由模型与数据共同学习差异。

数据不平衡则按每个 task-robot 组合的样本数 `n^0.43` 分配权重：比原始比例温和，避免大数据组合完全支配训练；又不像完全均匀采样那样过度重复小数据。

## 为什么 pre-training 与 post-training 需要两种数据性格？

```text
多样但不总是完美的 pre-training data
→ 学会许多场景、错误、纠正和恢复
→ 得到“什么都会一点”的 base policy

少量但策略一致、动作流畅的 post-training data
→ 告诉模型在目标任务上应偏好哪种执行风格
→ 得到专门而稳定的 task policy
```

pre-training mixture：

- 自采 π 数据超过 10,000 小时、903M timesteps，其中 single-arm 106M、dual-arm 797M；
- 7 类 configuration、68 个宽粒度 task；每个 task 内包含许多物体和行为，而不是把每个 noun-verb 组合都算新任务；
- 加入 OXE/BridgeData V2/DROID 等开放数据；在实际 training mixture 中开放数据权重为 9.1%；
- 同时用 task name 和约 2 秒的 segment annotation 作为语言标签。

post-training 数据按任务变化很大，简单任务约 5 小时，最复杂任务可达 100 小时以上。高层语义复杂的任务还可使用独立 high-level VLM 产生中间语言命令；这不是 π₀ 自己在 action tokens 中隐式完成完整规划。

## 实验怎样逐层回答设计问题？

### 1. Pre-trained base 能否直接做任务？

![[pi0-fig7-out-of-box.png]]

Figure 7 在 5 个 pre-training 分布内任务上每种方法各做 10 episodes：完整训练 700k steps 的 π₀ 全面最好；只训 160k steps、与 baseline update 数量相当的 π₀-parity 仍胜过所有 baselines；π₀-small（470M、无 VLM 初始化）也优于 OpenVLA/Octo，但明显落后于完整 π₀。

可支持：action-chunk flow 架构在该混合数据与任务上有效，VLM 初始化进一步提高表现。不能支持：模型对未见任务是 zero-shot；这些任务本就在 pre-training distribution 中，所以论文称 out-of-box，不应写成严格 unseen zero-shot。

### 2. VLM 预训练真的带来语言跟随吗？

Figure 9 比较 π₀ 与 π₀-small。三项任务的语言遵循率中，π₀ 约为 `0.95 / 0.70 / 0.91`，π₀-small 约为 `0.70 / 0.32 / 0.31`；π₀ 能从人工中间指令和 autonomous high-level VLM 指令中获益，而 small model 提升有限。

但这不是纯净的“只差 VLM 初始化”消融：π₀-small 更小、架构也不同。论文自己承认该混杂，因为大模型从头训练容易过拟合。

### 3. 新任务少量数据微调是否受益于预训练？

Figure 11 在 stack bowls、towel folding、Tupperware in microwave、paper towel replacement、items in drawer 上比较 1/5/10 小时数据，每点 10 trials。π₀ 通常优于 scratch π₀、ACT、Diffusion Policy 以及可比较的 OpenVLA/Octo；与预训练越相似的任务收益通常越明显，但 hard unseen-object/task 也有提升。

这支持预训练是更强起点，却没有隔离“哪些 pre-training 数据产生了迁移”。

### 4. Pre-train + post-train 是否优于只用其中之一？

![[pi0-fig13-post-training.png]]

Figure 13 的 7 个复杂任务每项 10 trials：完整 `pre-trained + fine-tuned` π₀ 全部超过最大 rubric score 的 50%，整体优于 out-of-box 和 scratch。对 pre-training 已包含的 laundry/table/mobile/dryer 任务，post-training 提升执行流畅性；对 box/to-go box/packing eggs 等未包含任务，预训练有时帮助显著，但 packing eggs 中 scratch 与完整模型接近，说明迁移并非每项必胜。

## π₀、π₀.5 与 HyVLA 的关系

| 维度 | π₀ | [[π₀.5]] | [[Hy-Embodied-0.5-VLA]] |
|---|---|---|---|
| 核心主张 | VLM + Flow Action Expert 可扩展到灵巧跨机器人控制 | heterogeneous co-training 推向 open-world generalization | embodied-native MoT + UMI 数据与完整 post-training/deployment stack |
| state 注入 | 单独 state token，走 Action Expert | 需以 π₀.5 原文为准，不沿用本页结论 | 独立 state block/token 路径 |
| timestep 注入 | action embedding MLP 拼 sinusoidal τ | 不应假定与 π₀ 相同 | Action Expert 中的 conditioning 设计另见原文 |
| 动作统一 | pad 到 18D，保留各平台 representation | heterogeneous action representations | canonical 20D relative EEF chunk |
| chunk 执行 | 执行 16/25 步后丢弃余下，无遮罩聚合 | 依后续论文 | 异步推理 + Bézier 拼接 |

π₀ 是后续体系的架构祖先，但不能看到相同名词就假定实现没变，尤其是 state/timestep injection、action coordinate、data mixture 与推理策略。

## 论文没有解决什么？

- 数据配方：作者把所有可用数据混在一起，尚不知道哪类任务、机器人或质量等级最有迁移价值；
- scale prediction：无法预测一个任务需要多少小时、什么类型的数据才能接近可靠；
- universal transfer：跨 7 类 manipulation robot 的共享，不代表已证明能迁移到自动驾驶、导航或腿足；
- 评测规模：多数真实任务每条件 10 trials，适合展示趋势，但对相近方法差距的统计置信度有限；
- 高层规划：复杂任务的一部分依赖独立 VLM 或人工中间语言，不应全部算作单一低层 π₀ policy 的长时推理；
- safety/force：论文重点是视觉、状态和位置/关节动作，没有触觉与显式力控，接触丰富不等于接触可观测；
- 开源性：该论文描述方法与数据规模，但是否能完整复现实验取决于未公开数据、硬件与训练基础设施。

## 对 Claude HTML 的吸收与纠错

保留了它的优点：按问题推进、实现式伪代码、mask 玩具矩阵、Flow 与 KV Cache 的连续因果链。以下信息按 PDF 修正：

1. π₀ 报告的是 **7 类 robot configurations**，不是把所有相近硬件拆成更多独立类别；
2. block-wise mask 不会阻止 action loss 反向更新 VLM，论文也没有描述专门的 VLM auxiliary CE loss；
3. `τ` 的论文分布是 `p(τ)=Beta((s-τ)/s;1.5,1)`，不能随意改写为另一个 Beta 参数化；
4. 50 Hz 是动作执行频率，模型重规划约每 0.5 秒一次；
5. Figure 7 是 pre-training distribution 内的 out-of-box 评测，不是严格 unseen zero-shot。

## 回顾时先回答七个问题

1. 为什么 VLM token 与 state/action token 不共用 FFN？
2. P/S/A 三块中，哪条注意力路径必须禁止，为什么？
3. 为什么 action block 内可以双向注意而不构成“偷看未来”？
4. `Aτ` 和目标速度 `A−ε` 怎样从一个 toy example 算出来？
5. 73 ms 为什么没有乘以 10 变成 730 ms？
6. 跨机器人到底统一了维度，还是统一了物理坐标语义？
7. 哪些实验隔离了架构收益，哪些仍混入模型规模与数据差异？
