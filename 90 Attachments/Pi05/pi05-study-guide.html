01

从实验室到真实世界——π₀.5 要解决什么问题

现有的 VLA 模型在实验室里表现很好，但搬到新环境就不行了。π₀.5 要解决的是"开放世界泛化"。

在 π₀ 学习指南中，我们看到 π₀ 已经能在 7 种机器人构型上实现灵巧操作。但 π₀ 有一个根本局限：它是在实验室环境中训练和评估的。当机器人走出实验室——进入一个从未见过的真实家庭厨房——它面对的是完全不同的桌面布局、未见过的碗碟样式、不同的抽屉把手和陌生的灯光条件。

π₀.5 要回答一个关键问题：一个学习系统能否让机器人在完全陌生的真实家庭中，执行 10-15 分钟的复杂长程任务？

为什么"开放世界泛化"这么难？

考虑一个看似简单的指令——"把厨房收拾干净"。机器人需要：识别哪些东西该放进水槽（碗、盘子、杯子——包括从未见过的样式）；判断哪些东西该放进抽屉（餐具——但这个抽屉的位置和把手样式都是新的）；规划子任务顺序（先收盘子还是先擦桌子？）；持续执行 5-10 分钟不出错。

每一步都涉及不同层次的泛化能力：视觉识别（新物体）、语义理解（什么算"干净"）、运动控制（新的抽屉位阻力不同）、长程规划（子任务排序）。单纯靠增加机器人操作数据无法解决所有问题——因为你不可能在所有家庭中采集数据。

π₀.5 的答案：两个核心思路

思路一：多源异构数据协同训练——不只用机器人操作数据，还要用其他机器人的数据、互联网图文数据、语义标注数据和人类口头指令数据。不同数据源教会模型不同层次的能力。

思路二：分层推理（Hierarchical Inference）——模型先预测一个高层子任务（如"拿起盘子"），再基于这个子任务生成低层连续动作。同一个模型扮演两个角色：高层规划者和低层执行者。

# π₀.5 的整体工作流程
def pi05_clean_kitchen(images, high_level_cmd="clean the kitchen"):
    while task_not_done:
        # 第一步：高层推理——预测下一个子任务
        subtask = model.predict_subtask(images, high_level_cmd)
        # 输出示例："pick up the plate"

        # 第二步：低层推理——生成连续动作
        actions = model.predict_actions(images, subtask)
        # 输出：H=49 步的连续动作块

        # 执行动作，获取新观测
        images = robot.execute_and_observe(actions)

# 关键：高层和低层推理用的是 **同一个模型**
# 高层 = 自回归文本生成（和 LLM 一样）
# 低层 = Flow Matching 连续动作生成（和 π₀ 一样）

02

多源异构数据——"一生经验"的类比

人类泛化能力的来源不是"做过所有事情"，而是"融合了多种层次的经验"。

π₀.5 论文用了一个非常好的类比：一个人能在新厨房里做饭，不是因为他在世界上所有厨房都练习过，而是因为他积累了一生多种层次的经验——

有些能力来自直接实践（自己在家做过饭），有些来自观察他人（看别人怎么操作），有些来自书本知识（知道什么是碗、什么是抽屉），有些来自口头教导（别人告诉你"先洗碗再擦桌子"比较高效）。这些不同层次的知识共同构成了泛化能力。

π₀.5 的数据哲学

π₀.5 把这个类比直接搬到了模型训练中：

核心洞察：训练数据中 97.6% 不是来自目标平台（移动操作机器人），而是来自其他机器人、互联网数据和语义标注。但正是这些"非直接经验"的数据，教会了模型开放世界泛化所需的各种能力。

# π₀.5 的数据混合配方（Training Recipe）
training_recipe = {
    # ===== 机器人操作数据（"直接实践"）=====
    "MM": "移动操作机器人在真实家庭中的数据 ~400小时",
    "ME": "非移动机械臂在多种家庭环境中的数据",
    "CE": "实验室环境下各种构型机器人的数据",

    # ===== 非机器人数据（"间接经验"）=====
    "HL": "高层子任务预测标注",
    "WD": "互联网图文数据（看图说话、VQA、物体检测）",
    "VI": "人类口头指令示教（后训练专用）",
}

# 为什么这个混合配方有效？
# MM 教会：在家庭环境中移动和操作
# ME 教会：不同环境中的操作技能（更多样化的场景）
# CE 教会：更广泛的操作原语（抓取、折叠、擦拭...）
# HL 教会：把高层指令分解成子任务（规划能力）
# WD 教会：识别各种物体和场景（视觉泛化）
# VI 教会：什么样的子任务序列是合理的（高层推理质量）

VLA 框架使异构数据训练成为可能

关键技术前提是 VLA（Vision-Language-Action）框架的灵活性。通过把所有模态——图像、文本、动作——都编码成 token 序列，不同来源的数据可以用同一套 Transformer 架构处理。论文怎么处理不同数据类型的输出？

数据源输入输出训练方式
MM/ME/CE图像 + 指令 + 状态FAST 离散化动作 token自回归 next-token
HL图像 + 高层指令子任务文本 + 边界框自回归 next-token
WD (captioning)图像描述文本自回归 next-token
WD (VQA)图像 + 问题答案文本自回归 next-token
WD (detection)图像 + 类别名边界框坐标自回归 next-token
VI图像 + 口头子任务指令动作Flow Matching（后训练）

注意一个巧妙之处：在预训练阶段，所有输出都是离散 token（包括动作，通过 FAST 编码器离散化）。这意味着预训练就是一个标准的自回归语言模型训练——和训练 GPT 没有本质区别。这让训练非常高效和稳定。

→ 衔接问题：我们知道了"混合训练"的哲学，但每种数据到底长什么样？它怎么被组织成 Transformer 的输入序列？下一节逐一拆解六种数据源。
03

六种数据源详解——每种数据教会模型什么

π₀.5 训练数据的每一种来源都有独特的贡献，缺一不可。

MM: Diverse Mobile Manipulator Data（核心机器人数据）

约 400 小时的移动操作机器人数据，采集自约 100 个不同的真实家庭环境。这是与最终部署场景最直接相关的数据——机器人在真实厨房、卧室中执行清理和整理任务。

# MM 数据的一条训练样本
mm_example = {
    "images": [wrist_cam_L, wrist_cam_R, forward_cam, backward_cam],
    "prompt": "<control_mode> joint/end effector <control_mode>\n"
              "clean the kitchen",
    "proprioceptive_state": [joint_angles_L, joint_angles_R,  # 2×6 DoF
                             gripper_L, gripper_R,             # 夹爪
                             base_vel_linear, base_vel_angular, # 底盘
                             torso_lift],                       # 躯干升降
    "actions": "FAST encoded discrete tokens",  # 预训练
    # 或 continuous action chunk [H=49, 18-19 dim]  # 后训练
    "subtask_label": "pick up the plate",  # HL 标注（如果有多子任务）
}

关于 100 个环境

100 个家庭环境听起来不多，但每个环境的物品摆放、灯光、背景都不同。论文的消融实验（Figure 8）显示：从 3 个环境增加到 104 个环境，模型性能稳步提升，且 104 个环境的模型接近在测试环境中训练的上界。这说明环境多样性比数据量更重要。

ME: Diverse Multi-Environment Non-Mobile Data

非移动机械臂（固定在桌面或支架上的单臂/双臂系统）在各种家庭环境中采集的数据。这些机械臂比移动操作机器人更轻便、更容易部署，所以能覆盖更多样化的家庭场景。

ME 数据的关键价值：虽然机器人构型不同（没有移动底盘），但操作技能（抓取、放置、开关抽屉）是可迁移的。消融实验显示，去掉 ME 数据后性能显著下降（p<0.001），说明跨构型的操作技能确实能迁移。

CE: Cross-Embodiment Laboratory Data

来自实验室环境的多种机器人数据，包括开源的 OXE（Open X-Embodiment）数据集的扩展版本。覆盖了非常广泛的任务类型：整理桌面、折叠衣服、擦拭表面等。

CE 数据的特殊之处：环境是标准化实验室（不是真实家庭），但任务种类极其丰富。它教会模型更广泛的操作原语——有些任务在 MM 数据中很少见（比如折叠衣服），但通过 CE 数据学会后，模型可以在新家庭中完成类似任务。

HL: High-Level Subtask Prediction

这是 π₀.5 相比 π₀ 的关键新增数据类型。对于 MM、ME、CE 中涉及多个子任务的数据，人工标注每个子步骤的语义描述和相关物体的边界框。

# HL 数据的标注示例
hl_annotation = {
    "high_level_cmd": "clean the bedroom",
    "observation": current_image,
    # 模型需要输出：
    "bounding_boxes": [
        "<loc0485><loc0871><loc0911><loc8197>=closet",  # 标注关键物体
    ],
    "subtask": "move to closet",  # 下一个子任务
}

# 训练时，模型学会：
# 1. 看到当前场景 → 定位相关物体（输出边界框坐标）
# 2. 理解高层指令 → 分解出下一步子任务
# 这个能力让模型在推理时能"自动规划"

类比 Chain-of-Thought：HL 数据让模型学会的能力，类似于 LLM 中的 Chain-of-Thought prompting。模型不是直接从"打扫卧室"跳到底层动作，而是先"思考"下一步该做什么（"先去衣柜那边"），再基于这个思考结果生成动作。这种分步推理显著提升了长程任务的成功率。

WD: Multi-Modal Web Data

来自互联网的多模态数据，包含四种任务：

任务数据源贡献的能力
Image CaptioningCapsFusion, COCO理解图像内容、场景描述
Visual QACambrian-7M, PixMo, VQAv2回答关于图像的问题
Object Localization多个检测数据集定位物体边界框坐标
Indoor Scene Data室内场景 + 家居物品标注理解家庭场景布局

WD 数据是模型开放词汇泛化的关键。消融实验显示，去掉 WD 后，模型在分布外（OOD）物体上的语言跟随率和成功率显著下降。原因很直观：训练数据中的机器人只见过有限种类的物体，但互联网图文数据覆盖了几乎所有常见家居物品。当模型在新家庭遇到从未操作过的 "漏斗" 或 "药瓶" 时，WD 数据提供的视觉-语义知识让它能识别并理解该物体。

VI: Verbal Instruction（仅后训练阶段使用）

一种独特的数据收集方式：专家用户用实时语言指令"遥操作"机器人。每一步，专家看着机器人的视角画面，说出应该执行的子任务指令（如"pick up the blue shirt"），机器人用已训练好的低层策略执行。

# VI 数据的收集过程
def collect_verbal_instruction_data():
    """专家相当于一个"人类高层策略"——只负责决策，不操作"""
    while task_not_done:
        # 1. 专家看到当前画面
        images = robot.get_observations()

        # 2. 专家说出下一个子任务
        subtask = expert_says("put the plate on the rack")

        # 3. 机器人的低层策略执行这个子任务
        actions = trained_low_level_policy(images, subtask)
        robot.execute(actions)

        # 记录 (images, subtask, actions) 三元组
        # → 提供了"好的子任务序列"的示范

# VI 数据只在后训练阶段使用（约占移动操作数据的 11%）
# 消融实验：去掉 VI 后高层推理质量显著下降

VI 数据的独特价值

VI 数据只有约 11% 的移动操作数据量，但它对高层推理质量的影响巨大（消融中 no VI 的性能显著下降）。原因是：常规的遥操作数据只有"动作"，没有对应的"语言子任务标签"。即使 HL 标注为这些数据补充了子任务标签，标注质量也不如 VI——因为 VI 中的语言指令是真正驱动行为的信号，标注的时序和内容更精确。

→ 衔接问题：六种数据准备好了，但它们格式完全不同——机器人动作是连续向量，子任务是文本，边界框是坐标。怎么把它们统一成一种训练方式？下一节看预训练阶段的"全离散化"策略。
04

预训练阶段——全离散化的统一自回归建模

把所有东西都变成离散 token，预训练就退化成标准的 next-token prediction——和训练 GPT 一模一样。

为什么要先"全离散化"？

π₀.5 训练分两个阶段。在第一阶段（预训练），π₀.5 做了一个大胆的选择：把机器人动作也离散化成 token，用 FAST 编码器把连续的动作块压缩成一串离散 token。这样，所有训练数据——图像描述、问答、子任务预测、动作预测——都变成了"给定输入 token 序列，预测输出 token 序列"的统一形式。

# FAST 编码器的工作方式（回顾 π₀ 指南）
def fast_encode(action_chunk):
    """把连续动作块压缩成离散 token 序列"""
    # action_chunk: [H, action_dim] 的连续向量
    # 1. 量化为整数序列
    # 2. 用类似 BPE 的压缩算法，把高频模式合并
    # 3. 输出一串离散 token（比原始长度短很多）
    return discrete_tokens  # 例如 [+22, 13, -34, 102, +18, ...]

# 解码时反向操作
def fast_decode(discrete_tokens):
    return action_chunk  # 恢复为 [H, action_dim] 连续向量

这样做的好处是巨大的：

"两个世界的最好"（Best of Both Worlds）：预训练用离散 token → 训练稳定、高效、可以利用标准语言模型训练基础设施；后训练加入 Flow Matching → 动作精度更高、支持多模态分布。离散化负责"大规模统一预训练"，Flow Matching 负责"精细动作生成"。

预训练的具体实现

# 预训练阶段配置
pretrain_config = {
    "backbone": "PaliGemma (SigLIP 400M + Gemma 2B)",
    "total_params": "~3B（VLM部分）",
    "steps": 280_000,  # 280k 梯度步
    "alpha": 0.0,       # 不使用 Flow Matching（α=0）
    "data_sources": ["MM", "ME", "CE", "HL", "WD"],
    # 注意：不包含 VI（VI 仅在后训练使用）
    "action_representation": "FAST discrete tokens",
    "training_objective": "standard next-token prediction",
}

# 预训练时，不同数据源的 prompt 格式
prompts = {
    "robot_data": "<control_mode> joint <control_mode>\n{task_instruction}",
    "captioning": "caption the image",
    "vqa":        "{question}",
    "detection":  "localize the {object_name}",
    "subtask":    "how would you {high_level_cmd}?",
}

预训练时的输入输出序列

每条训练样本被组织成一个统一的序列，送进标准自回归 Transformer：

# 不同数据类型的序列格式

# === 机器人操作数据（MM/ME/CE）===
# 输入: [图像tokens] [状态tokens] [指令tokens]
# 输出: [FAST动作tokens]  ← 自回归预测

# === 带子任务标注的数据（HL）===
# 输入: [图像tokens] ["how would you clean the bedroom?"]
# 输出: [边界框坐标tokens] [子任务文本tokens]
#       例如: "<loc0485>...=closet, move to closet"

# === 看图说话（WD-captioning）===
# 输入: [图像tokens] ["caption the image"]
# 输出: [描述文本tokens]
#       例如: "A kitchen counter with plates and utensils"

# === VQA（WD-vqa）===
# 输入: [图像tokens] ["How many desks are in the image?"]
# 输出: ["12"]

# 所有输出都是离散 token → 统一的交叉熵损失
loss = cross_entropy(predicted_tokens, target_tokens)

动作数据的归一化和零填充

不同机器人的动作维度不同（移动操作平台 18-19 DoF，单臂 6-7 DoF）。π₀.5 沿用 π₀ 的做法：

# 跨构型动作处理
def normalize_actions(actions, robot_type):
    # 1. 归一化到 [-1, 1]：用每个数据集各维度的 1% 和 99% 分位数
    actions_norm = (actions - p1) / (p99 - p1) * 2 - 1

    # 2. 零填充到固定维度 a
    #    （用最大构型的维度，小构型的多余维度填0）
    actions_padded = zero_pad(actions_norm, target_dim=a)

    # 3. 文本 prompt 中标注控制模式
    #    "<control_mode> joint <control_mode>" 或
    #    "<control_mode> end effector <control_mode>"
    return actions_padded

预训练 280k 步的意义

280k 步是一个很大的训练量。π₀.5 在预训练阶段同时学到了：(1) 在各种环境中操作机器人的基础技能；(2) 识别和理解各种物体的视觉-语义知识；(3) 把高层任务分解为子步骤的规划能力。所有这些能力都以离散 token 预测的形式统一学习，稳定高效。

→ 衔接问题：预训练得到了一个强大的多任务自回归模型，但它输出的是离散动作 token——精度有限、推理时需要自回归解码（慢）。怎么让它输出高精度的连续动作？下一节看后训练阶段如何加入 Flow Matching。
05

后训练阶段——引入动作专家与 Flow Matching

在预训练基础上，加入一个随机初始化的"动作专家"，用 Flow Matching 学习生成高精度连续动作。

为什么需要后训练？

预训练阶段用 FAST 离散化动作有一个根本问题：离散化精度有限，且推理时需要自回归逐 token 解码（慢）。对于实时控制（50Hz），我们需要快速生成高精度连续动作。这正是 Flow Matching + 动作专家的优势——在 π₀ 指南中我们已经详细讨论过。

π₀.5 的后训练在预训练的 VLM 上嫁接一个全新的动作专家：

# 后训练阶段的模型结构

后训练的组合损失函数

后训练阶段，模型同时学习两件事：(1) 文本预测（子任务、描述等）用交叉熵损失；(2) 连续动作生成用 Flow Matching 损失。两者的组合：

# 组合损失函数（论文 Equation 1）
def combined_loss(model, batch):
    """
    L = H(text_cross_entropy) + α · ||flow_matching||²
    """
    images, prompt, state = batch["obs"]

    # === 文本部分：标准自回归交叉熵 ===
    text_logits = model.vlm_forward(images, prompt)
    H_text = cross_entropy(text_logits, batch["text_targets"])
    # text_targets 包括：FAST 动作 token、子任务文本、
    # 看图说话输出、VQA 答案等

    # === 动作部分：Flow Matching ===
    A_true = batch["continuous_actions"]   # [H=49, action_dim]
    epsilon = randn_like(A_true)           # 噪声
    tau = sample_beta_distribution()       # 时间步

    A_noisy = tau * A_true + (1 - tau) * epsilon
    v_pred = model.action_expert_forward(images, prompt, state, A_noisy, tau)
    v_target = A_true - epsilon

    flow_loss = MSE(v_pred, v_target)

    # === 组合 ===
    alpha = 10.0  # Flow Matching 权重
    total_loss = H_text + alpha * flow_loss
    return total_loss

α = 10.0 的含义：Flow Matching 损失的权重是文本损失的 10 倍。这说明后训练的主要目标是学好连续动作生成，文本预测（子任务等）在预训练阶段已经学得不错了，后训练只需要"维持"这个能力。α 太小，动作专家学不好；α 太大，文本能力会退化。

预训练阶段 CE 数据帮助模型学习广泛的操作原语，但后训练的目标是专门化——让动作专家精通移动操作平台的控制。CE 中的实验室数据此时反而是噪声，可能干扰动作专家学习目标平台的精细控制。这体现了"先泛化再专精"的训练哲学。

→ 衔接问题：后训练阶段，模型里同时存在两种动作表示——VLM 中的 FAST 离散 token 和动作专家中的连续嵌入。这两者怎么在一个 Transformer 里共存而不互相干扰？下一节看 π₀.5 独特的注意力掩码设计。
06

注意力掩码——隔离两种动作表示

π₀.5 的掩码比 π₀ 更复杂，因为它需要防止 FAST 离散 token 和动作专家连续嵌入之间的信息泄露。

回顾 π₀ 的三块掩码

在 π₀ 中，我们有三个块：感知（图像+语言）、状态、动作。感知块看不到后两者，状态能看到感知，动作能看到所有——这是经典的块间因果设计。

但 π₀.5 多了一个新问题：它的 VLM 输出中同时包含 FAST 动作 token（用于预训练阶段的离散化动作预测），和动作专家的连续嵌入（用于后训练阶段的 Flow Matching）。这两种动作表示不能互相看到——否则一种表示会从另一种中"作弊"获取信息。

掩码设计的三个关键决策

决策 1：FAST token 和动作专家嵌入互不可见。这是最重要的设计。论文原文说得很清楚："to avoid information leakage between the two representations of actions"。如果 FAST token 能看到动作专家嵌入（或反过来），模型可能学会"偷看"另一种表示来走捷径，而不是真正独立地学好两种生成方式。

决策 2：FAST token 之间是自回归的。因为 FAST 是离散 token，必须一个接一个地生成（和语言模型生成文本一样）。所以 fast₂ 能看到 fast₁，但 fast₁ 看不到 fast₂。

决策 3：动作专家嵌入之间是双向的。和 π₀ 一样，Flow Matching 的 H=49 个动作 token 需要同时去噪，所以它们之间必须双向可见，才能协调一致的轨迹。

# π₀.5 注意力掩码构造
def build_pi05_mask(n_img, n_prompt_state, n_fast, n_action_expert):
    N = n_img + n_prompt_state + n_fast + n_action_expert
    mask = zeros(N, N)  # 全 False

    i = n_img
    ps = n_prompt_state
    f = n_fast
    ae = n_action_expert

    # Image tokens: 看到 Image（双向，前缀）
    mask[0:i, 0:i] = True

    # Prompt+State: 看到 Image + Prompt+State（前缀）
    mask[i:i+ps, 0:i+ps] = True

    # FAST tokens: 看到前缀(Img+P+S) + 自回归看前序FAST
    for j in range(f):
        mask[i+ps+j, 0:i+ps] = True          # 看到前缀
        mask[i+ps+j, i+ps:i+ps+j+1] = True   # 自回归

    # Action Expert: 看到前缀(Img+P+S) + AE之间双向
    # 但看不到 FAST tokens！
    ae_start = i + ps + f
    mask[ae_start:, 0:i+ps] = True           # 看到前缀
    mask[ae_start:, ae_start:] = True         # AE 之间双向
    # mask[ae_start:, i+ps:ae_start] 保持 False  ← 看不到 FAST

    return mask

与 π₀ 掩码的关键区别：π₀ 只有三块（感知、状态、动作），动作块只有一种表示（Flow Matching 连续嵌入）。π₀.5 多了一个 FAST 离散 token 块，且这两种动作表示必须互相隔离。这使得信息流变成了单向的：VLM 的信息（图像、语言、状态）流向两种动作表示，但两种动作表示之间不交流。

→ 衔接问题：动作专家接收噪声动作和时间步 τ，但 π₀.5 注入 τ 的方式和 π₀ 不同——它用了 Adaptive RMSNorm 逐层注入。下一节看这个改进。
07

时间步编码的改进——Adaptive RMSNorm

π₀ 把时间步 τ 和噪声动作混合后送入 Transformer；π₀.5 用更细腻的方式——在每一层独立注入时间步信息。

回顾 π₀ 的做法

在 π₀ 中，时间步 τ 和噪声动作在输入阶段就融合了：token = MLP(concat(a_noisy, φ(τ)))。τ 信息只在输入时注入一次，之后 Transformer 的 18 层都在用同一个混合后的表示。

π₀.5 的改进：逐层注入

π₀.5 把 τ 的处理分成两部分：

# π₀.5 的时间步编码方案

# 第一部分：噪声动作的嵌入（不再混合 τ）
def embed_noisy_action_pi05(a_noisy, action_dim, expert_width=1024):
    """只做线性投影，不包含时间步"""
    return linear_projection(a_noisy)  # [action_dim] → [1024]

# 第二部分：时间步用独立的 MLP 编码
def encode_timestep(tau, width=1024):
    """
    公式: swish(W2 · swish(W1 · φ(τ)))
    φ: R → R^w 是正弦位置编码
    """
    phi_tau = sinusoidal_encoding(tau)     # 标量 → [width]
    h = swish(W1 @ phi_tau)               # [width] → [width]
    timestep_emb = swish(W2 @ h)          # [width] → [width]
    return timestep_emb                    # 这个嵌入会被用在每一层

# 第三部分：在动作专家的每一层，用 Adaptive RMSNorm 注入 τ
def action_expert_layer(x, timestep_emb, layer_idx):
    """
    Adaptive RMSNorm: 用时间步嵌入调制归一化的 scale
    类似于 StyleGAN 中的 Adaptive Instance Norm
    """
    # 标准 RMSNorm
    x_norm = rms_normalize(x)

    # Adaptive: scale 参数由 timestep_emb 生成
    gamma = linear_layer(timestep_emb)  # τ → 每一层独特的 scale
    x_scaled = gamma * x_norm

    # 后续正常做注意力和 FFN
    x = attention(x_scaled, ...)
    x = ffn(x)
    return x

为什么 Adaptive RMSNorm 更好？

逐层调制 vs 一次性混合：π₀ 的做法相当于在输入时告诉模型"你现在在去噪阶段 τ=0.3"，然后整个 Transformer 用同一个混合信号处理。但 Transformer 的不同层可能在做不同层次的事——浅层处理局部特征，深层处理全局语义。Adaptive RMSNorm 让每一层都根据 τ 独立调整自己的行为——浅层在 τ=0.3 时强调粗略方向，深层在 τ=0.3 时关注中等精度的协调。

直觉类比：想象你在指导一个团队画画。π₀ 的方式是开会时说一句"我们现在画到 30% 了"，然后每个人自己理解该做什么。π₀.5 的方式是走到每个人旁边，根据他们的具体工作（轮廓、色彩、细节）分别调整指导——对画轮廓的人说"大胆一些"，对上色的人说"色块先到位"。

动作输出头

经过 18 层处理后，动作专家输出的 token 通过一个线性层映射回动作空间，得到预测的速度场：

# 动作专家输出
def action_expert_output(expert_output_tokens):

→ 衔接问题：现在我们有了完整的模型架构。但推理时，同一个模型怎么既预测子任务文本又生成连续动作？下一节看分层推理的工作流程。
08

分层推理——同一模型的两种工作模式

π₀.5 的分层推理是它最强大的特性：用同一个模型，先"思考"下一步做什么，再"执行"具体动作。

两种推理模式

π₀.5 在推理时交替使用两种模式，都由同一个训练好的模型执行：

# 模式一：高层推理（子任务预测）
def high_level_inference(model, images, high_level_cmd):
    """
    工作方式：标准自回归文本生成（和 ChatGPT 一样）
    输入：4 张相机图像 + 高层指令（如 "clean the bedroom"）
    输出：下一个子任务文本（如 "pick up the pillow"）

    使用哪个专家：仅 VLM 专家
    不使用动作专家（不需要连续动作）
    """
    prompt = f"how would you {high_level_cmd}?"
    # 自回归逐 token 生成
    subtask_tokens = []
    for _ in range(max_tokens):
        next_token = model.vlm_next_token(images, prompt, subtask_tokens)
        if next_token == EOS:
            break
        subtask_tokens.append(next_token)

    subtask_text = detokenize(subtask_tokens)
    return subtask_text  # 例如 "pick up the pillow"


# 模式二：低层推理（连续动作生成）
def low_level_inference(model, images, subtask):
    """
    工作方式：Flow Matching 10 步去噪（和 π₀ 一样）
    输入：4 张相机图像 + 子任务文本 + 机器人状态
    输出：H=49 步的连续动作块

    使用哪个专家：VLM + 动作专家联合
    VLM 处理图像和文本，动作专家处理动作
    """
    state = robot.get_proprioception()
    A = randn(49, action_dim)  # 从纯噪声开始

    # 10 步欧拉积分
    for step in range(10):
        tau = step * 0.1
        v = model.forward(images, subtask, state, A, tau)
        A = A + 0.1 * v

    return A  # 49 步的连续动作

完整的推理循环

# π₀.5 的完整推理循环（以 "清理厨房" 为例）
def pi05_full_inference(high_level_cmd="clean the kitchen"):
    """
    整个循环可能持续 10-15 分钟
    高层推理频率远低于低层推理
    """
    step = 0
    while not done:
        images = robot.capture_all_cameras()  # 4 张图

        # ===== 高层推理：决定下一步做什么 =====
        # 使用所有 4 个相机（前/后/左右手腕）
        subtask = high_level_inference(model, images, high_level_cmd)
        print(f"Step {step}: {subtask}")
        # 可能输出：
        #   Step 0: "pull out the drawer"
        #   Step 1: "pick up tong"
        #   Step 2: "put tong into drawer"
        #   Step 3: "push the top drawer"
        #   ...

        # ===== 低层推理：执行这个子任务 =====
        # 只使用前向 + 手腕相机（不用后向相机）
        while subtask_not_completed:
            images_low = robot.capture_low_level_cameras()
            actions = low_level_inference(model, images_low, subtask)
            robot.execute(actions)  # 执行 49 步动作

            # 动作块执行完，检查是否需要新的子任务
            if need_new_subtask():
                break

        step += 1

高层和低层推理使用不同的相机

推理模式使用的相机原因
高层推理全部 4 个（前向 + 后向 + 2 个手腕）需要全方位了解场景，规划下一步
低层推理前向 + 2 个手腕（不用后向）只需看操作区域，后向相机对精细控制无用

为什么同一模型能做两件事？

这个设计的精巧之处在于训练数据的组织方式。在训练时：

HL 数据教会了高层推理：模型看到 (图像, "how would you clean the bedroom?") → 学会输出 "pick up the pillow"。这和 LLM 学会回答问题的方式完全一样——自回归生成文本。

MM/ME 数据教会了低层推理：模型看到 (图像, "pick up the pillow", 状态, 噪声) → 学会输出速度场 → 去噪得到动作。这和 π₀ 的 Flow Matching 完全一样。

推理时，只需要切换 prompt 格式和推理方式，模型就能在两种角色之间切换。这比用两个独立模型（一个规划器 + 一个控制器）更简洁，因为高层和低层共享了视觉理解能力——两者对"枕头在哪里""抽屉怎么打开"的理解是一致的。

超越 GPT-4 的高层策略

消融实验中，π₀.5 的高层推理甚至超过了用 GPT-4 做高层策略的性能（Figure 13）。原因：GPT-4 虽然很聪明，但它没有操作经验——它可能知道应该"把盘子放进水槽"，但不知道对于这个特定的机器人和场景，从哪个角度操作最高效。π₀.5 的高层推理融合了互联网语义知识和实际操作经验，所以更实用。

局限性和未来方向

论文坦诚地讨论了 π₀.5 的局限：

局限具体表现可能的解决方向
物理障碍某些抽屉把手太难操作更大的训练数据多样性
遮挡问题机械臂挡住了要擦的污渍更丰富的相机视角、触觉传感
高层推理偏差反复开关抽屉等循环行为更多 VI 数据、更长的上下文窗口
指令复杂度只能处理简单的高层指令更复杂的标注和训练数据
空间记忆不记住物品在哪个房间引入记忆模块、更大上下文

总结——π₀.5 的核心贡献：(1) 证明了多源异构数据协同训练可以赋予 VLA 模型开放世界泛化能力；(2) 用同一个模型实现了高层规划和低层控制的统一；(3) 首次展示了端到端学习的机器人在完全陌生的真实家庭中完成长程复杂任务。这标志着 VLA 从"实验室演示"走向"真实世界部署"的重要一步。
