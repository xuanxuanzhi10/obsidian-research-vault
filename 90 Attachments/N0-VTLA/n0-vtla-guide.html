01

定位与背景：为什么 VLA 需要触觉？

现有的 VLA 模型全都围绕视觉和语言构建——它们看得清楚、听得明白，但"摸不着"。这在接触密集的操作任务中暴露了系统性弱点。

从 π₀ 到 π₀.₅，再到 OpenVLA，VLA 模型已经展示了跨任务、跨场景、跨机器人的泛化能力。但它们的观测空间始终以摄像头、语言指令和机器人状态为中心。当任务的成败取决于接触力度、滑移感知、形变反馈时——比如插拔插头、折叠毛巾、立瓶子——纯视觉策略就显得力不从心了。

N₀-VTLA（读作 NeoVTLA）的核心命题：触觉不该被当成"再来一路摄像头"塞进 VLA，而应被重新定位为一个预测目标。模型不是被动地读取当前触觉帧，而是主动预测接下来 50 步（一个 action chunk）的接触变化，然后让 Action Expert 基于这个预测来生成动作。

一句话定位：N₀-VTLA = π₀.₅ backbone + 冻结 DINOv2 触觉编码器 + Latent Tactile Predictor + ALTER 离线 RL。它是首个在大规模触觉数据上预训练的 VTLA 模型。

现有触觉集成路径的问题

论文梳理了两条已有的触觉集成路线，并指出各自的缺陷：

路径做法问题代表工作
路径 A：前缀拼接 触觉 token 拼入 vision–language context 触觉信号稀疏且大部分时间静默，浪费了为信息密集视觉设计的前缀容量 OmniVTLA, Tactile-VLA
路径 B：动作注入 当前触觉读数注入 action pathway 引导去噪 当前触觉帧记录的是已经发生的接触，对即将到来的接触没有前瞻性；策略始终"慢一拍" Reactive Diffusion Policy, TouchGuide
路径 C（本文） 触觉不进前缀，而是预测未来触觉变化的潜变量 z 直接 condition Action Expert —— N₀-VTLA
回顾：π₀.₅ 的架构基础

N₀-VTLA 直接继承了 π₀.₅ 的完整架构：PaliGemma VLM backbone + Flow Matching Action Expert，32 维 canonical action space，H=50 的 action chunk horizon。如果你记得 π₀.₅ 指南中的 Action Expert 如何从 vision-language prefix 中做 cross-attention，这里的结构完全一样——唯一的区别是现在 Action Expert 多了一组 latent tactile tokens z 作为额外的 conditioning。

→ 衔接：我们知道了"为什么需要触觉"以及"现有方案的缺陷"。下一节拆解完整架构——触觉信号如何从传感器一路流到动作生成。
02

架构拆解：从输入到输出的完整数据流

N₀-VTLA 的架构可以拆成两大部分：继承自 π₀.₅ 的 base policy，和新增的 latent tactile pathway。我们从全局视角走一遍数据流。

输入端

每个时刻，模型接收四类输入：

输入来源去向
RGB 图像（3 视角）第三方+两个手腕摄像头→ Vision-Language Prefix
语言指令自然语言任务描述→ Vision-Language Prefix
机器人状态关节/末端执行器→ 离散化后进入 Prefix
触觉差分图像每根夹爪手指的自研 visuo-tactile 传感器→ Tactile Encoder → Latent Tactile Predictor（不进 Prefix!）
注意

触觉信号永远不进入 vision-language prefix。这是本文最核心的架构决策之一。触觉 tokens 只通过 predictor 蒸馏成 latent z，z 直接 condition Action Expert。

完整数据流伪代码

# ===== N₀-VTLA 前向推理 =====

# 1. Vision-Language Prefix (继承自 π₀.₅)
prefix = PaliGemma.encode(rgb_views, instruction, robot_state)
#   prefix: [B, L_prefix, d]  —— 场景+指令+状态的上下文表示

# 2. Tactile Encoding (冻结 DINOv2 + 可训练 projection)
for k in range(n_views):  # n 个触觉视角 (单臂=2, 双臂=4)
    tac_diff_k = tac_current_k - tac_baseline_k   # 像素空间差分，去除静态凝胶外观
    g_k = Linear_proj(frozen_DINOv2(tac_diff_k))   # [B, 10, d]  (1 cls + 9 spatial)
g = concat(g_1, ..., g_n)                          # [B, 10n, d]

# 3. Latent Tactile Predictor
z = Predictor(g, prefix)                           # [B, 10, d]
#   输入: 当前触觉 tokens g + 视觉语言上下文
#   输出: latent tactile tokens z —— 预测未来 H=50 步的接触变化

# 4. Action Expert (Flow Matching, 继承自 π₀.₅)
z_proj = project_to_expert_width(z)                # 投影到 action expert 维度
action_tokens = [z_proj; noised_actions]           # z 前置于 noisy action tokens
#   action tokens attend to z AND prefix (Step 3之后)
#   z positions 在输出前被切掉，不产生 action
predicted_chunk = FlowMatching.denoise(action_tokens, prefix)
#   predicted_chunk: [B, H=50, 32]  —— 32维 canonical action space

关键架构特点

触觉编码器为何冻结？论文使用冻结的 DINOv2 作为触觉编码器，只训练一个轻量级线性投影层。三个理由：（1）保留自监督表示的完整性；（2）让新传感器只需训练投影层即可接入；（3）节省训练显存——编码器的激活和优化器状态不占训练预算。

10 个 tokens 的来源：DINOv2 产出 16×16 的 patch grid，经过 3×3 adaptive average pooling 得到 9 个 spatial tokens，加上 1 个 class token，共 10 tokens per tactile view。

差分编码而非绝对编码：每集开头 0.5 秒静止期录制"零接触基线帧"，后续所有触觉帧在像素空间减去该基线。这移除了静态凝胶外观和传感器安装差异，使表示对传感器放置位置具有鲁棒性。

亮点

架构上的"触觉不进 prefix"决策非常优雅。Vision-language prefix 为信息密集的视觉信号设计，而触觉信号大部分时间是空的——只在接触形成或变化的短暂窗口才有信息。把稀疏信号硬塞进信息密集通道是一种结构性浪费。

回顾：与 π₀.₅ 的架构对比

π₀.₅ 的数据流：RGB + 指令 + 状态 → PaliGemma prefix → Flow Matching Action Expert → action chunk。N₀-VTLA 在此基础上新增了一条旁路：触觉差分图像 → 冻结 DINOv2 → Predictor → latent z → condition Action Expert。关键是这条旁路与 prefix 平行而非串行——z 直接进入 Action Expert 的 attention，prefix 不会 attend back to z。

→ 衔接：我们理解了整体数据流。下一节深入 latent tactile tokens 的核心机制——为什么"预测"比"反应"更好，以及 z 到底在预测什么。
03

核心机制：Latent Tactile Tokens 的预测式设计

N₀-VTLA 的核心创新不在于加了触觉，而在于触觉的使用方式——让模型预测即将到来的接触，而不是对已发生的接触做出反应。

为什么预测而非反应？

论文提出了一个关键洞察：触觉最重要的场景恰恰是"前接触盲区"。比如：

夹爪关闭前的毫米级预加载（pre-load）、物体即将滑移前的细微力调整——这些行为是预期性的（anticipatory）。当纯反应式的触觉信号到达时，引发接触的动作已经执行完了。策略永远慢一拍。

核心哲学：决定一个 50 步 action chunk 的，是这个 chunk 即将产生的接触，而不是当前帧中已经存在的接触。当前帧的任何编码都不包含未来接触信息。

z 在预测什么？

Latent tactile tokens z 的训练目标 z*（在 Stage 1 中使用）定义为：

# z* = 未来 H=50 步的净触觉变化的编码
# 对每个触觉视角 k:
future_tac_diff_k = tac_{τ+H}_k - tac_{τ}_k   # 未来 H 步的触觉变化
z_star_k = frozen_DINOv2(future_tac_diff_k)     # 编码后的未来触觉
z_star = mean(z_star_1, ..., z_star_n)           # 跨视角平均
# z_star: [B, 10, d]  —— 这就是 predictor 要去匹配的目标

# Predictor 的输出 z ∈ R^{10×d} 被训练去匹配 z*
# 用 symmetric InfoNCE + L1 reconstruction loss

注意关键的区分：tac_{τ+H} - tac_{τ} 是未来触觉变化（τ到τ+H），而编码器的输入 tac_{τ} - tac_0 是当前触觉状态（相对于episode开头）。z* 编码的是接下来50步会发生什么样的接触变化。

Predictor 能预测多准？

Stage 1 训练完成后，在 378 个 held-out query 上，z 检索其匹配的 z*（在约32个候选中）的 top-1 准确率达到 92.3%，而随机基线仅 3.2%。

作为对照，仅用当前触觉编码 g（不经过 predictor）检索未来触觉目标只有 57% top-1。这证明 predictor 确实学到了超越当前输入的前瞻性信息。当候选池增大到 128 个时，predictor 仍有 81%，而 g 降到 40%——差距随难度增长而加大。

与 JEPA 系列的关系

这种"在学到的 latent space 中预测，而不是重建原始信号"的思路，直接沿袭了 Joint-Embedding Predictive Architecture (JEPA) 的理念：

方法预测目标预测空间
I-JEPA图像的 masked patcheslearned latent space
V-JEPA视频帧的未来 patchlearned latent space
LeWorldModel未来像素的 latentlearned latent space
N₀-VTLA未来触觉变化的 latentDINOv2 feature space

区别在于 N₀-VTLA 的 latent space 不是学出来的，而是冻结 DINOv2 的 feature space——这让目标更稳定，也避免了 representation collapse。

亮点

预测式触觉设计有明确的实验支撑。Figure 10 的 counterfactual probe 直接证明了：在同一观测、同一采样噪声下，有触觉和无触觉的动作轨迹在接触关键时刻分叉，在自由空间中重合。触觉路径在该"沉默"时沉默，在该"发言"时发言。

注意

Free-latent 变体：论文定义了一个简化版本，完全跳过 Stage 1 的监督，z 仅通过 action gradient 塑造。这不需要未来触觉帧。虽然论文认为它是设计空间中的有效点，但实验表明全监督版本更好。

04

训练数据：NeoData 与跨平台规范化

大规模触觉预训练的前提是大规模触觉数据。NeoData 是论文构建的多平台视觉-触觉机器人数据集。

NeoData 语料库

NeoData 覆盖单臂和双臂机器人操作平台（ARX X5、UR5e、Flexiv、Franka、Piper），以及 UMI 风格的手持采集夹爪（Neo TacUMI）。每根参与操作的夹爪手指都安装了自研的 visuo-tactile 传感器，触觉以图像流的形式读出。

字段规格
模态3 RGB 视角 + 语言指令 + 本体感受 + 2/4 触觉流
帧率30 fps，所有模态统一
RGB 分辨率原始 640×480，训练时 resize 到 224×224
格式LeRobot dataset format
语言标注每任务多个 paraphrase 变体

Canonical Action and State Schema

这是从 π₀.₅ 直接继承的 32 维 canonical container：

# 32维 canonical action/state container
# 前 20 维: 2个 arm slot × 10维/slot
#   每个 slot: [position_3d, rot6d_6d, gripper_1d] = 10 维
# 后 12 维: 始终为零（未使用）

# 单臂 episodes: 只填第一个 slot，第二个 slot 全零
# 双臂 episodes: 两个 slot 都填
# 模型学会对零填充维度输出零 —— 单臂和双臂数据共存于一个模型
回顾：π₀.₅ 的跨机器人统一

如果你记得 π₀.₅ 指南，这个 32 维 container 设计是 π₀.₅ 的关键创新之一——它让不同形态的机器人数据可以在同一个 flow matching objective 下共同训练。N₀-VTLA 完全继承了这一设计，意味着触觉数据也通过同一个 container 接入。actions 存储为绝对末端执行器 poses，训练时转为 chunk-relative（相对于每个 chunk 的第一帧）。

触觉采集规范

每个 episode 开头至少 0.5 秒的夹爪打开静止期，录制零接触基线帧。后续所有触觉帧相对于这个基线解释。这保证了差分编码 tac_τ - tac_0 的一致性。

数据质量验证

论文在 Appendix C 列出了 9 条"红线"（不变量），每条都配了违反时的症状。例如：

— 动作没存为绝对末端执行器 poses → 训练 loss 正常下降，但策略在真机上无法使用
— 视频 GOP（group of pictures）超过 30 帧 → 训练吞吐量因周期性卡顿崩溃
— 缓存数据集未随数据更新而清除 → 训练静默读取过期缓存，loss 异常高且不收敛

亮点

数据工程的"红线-症状"对照表极其实用。这是很多大规模机器人学习项目踩过的坑，论文把它们系统整理出来，对社区有很大参考价值。

05

训练范式：三阶段触觉路径上线 + ALTER 离线 RL

把一个新初始化的触觉路径安全地嫁接到预训练好的 VLA 上，而不破坏已有能力——这需要精心设计的阶段式训练。

总体训练流程

# N₀-VTLA 的训练阶段全景
# ================================
# Phase A: Base Pre-training (在 NeoData 上，cluster scale)
#   → 得到 π₀.₅-style 的 VLA checkpoint

# Phase B: Three-Stage Latent-Tactile Training
#   Stage 1: Ground the predictor (冻结 base policy)
#   Stage 2: Align latents with action expert (冻结 predictor + VLM, mask prefix)
#   Stage 3: End-to-end joint training (解冻除触觉编码器外的一切)
#   → 得到 N₀-VTLA pretrained checkpoint

# Phase C: Supervised Task Adaptation (SFT)
#   几百条示范 → 微调到具体任务

# Phase D (可选): ALTER 离线 RL
#   从部署数据中学习 → 进一步提升

Stage 1：Grounding the Predictor

冻结什么：整个 base policy（VLM + Action Expert）。
训练什么：只训练 Predictor、触觉线性投影和重建头。
目标：让 z 编码有意义的未来触觉信息。

# Stage 1 Loss
s_ij = cosine_sim(mean_pool_l2norm(z_i), mean_pool_l2norm(z*_j))

L_NCE = -(1/2B) * Σ_i [
    log(exp(s_ii) / Σ_j exp(s_ij)) +   # z_i 检索 z*_i (正方向)
    log(exp(s_ii) / Σ_j exp(s_ji))      # z*_i 检索 z_i (反方向)
]

L_rec = || r_ψ(z) - D̄_{τ→τ+H} ||₁    # 重建粗糙的未来触觉差分场

L_1 = L_NCE + λ_rec * L_rec

# 为什么两个 loss？
# InfoNCE: 让 z 能检索到正确的未来触觉目标 (判别性)
# L1 重建: 锚定 z 到接触的空间布局 (防止捷径 latent)

因为梯度只流过浅层 predictor stack，这个阶段计算廉价、收敛快速。

Stage 2：Aligning Latents with Action Expert

冻结什么：Predictor（Stage 1 checkpoint）+ VLM backbone。
训练什么：latent-to-expert projection + Action Expert。
关键操作：Vision-language prefix 的 keys/values 对 action queries 被 mask 掉。

# Stage 2: Action Expert 只能通过 z 获取信息
# prefix → ✗ (masked, action queries 看不到)
# z → ✓ (action queries 只能 attend to z 和 noised actions)
#
# 效果: action loss 的唯一下降路径是学会从 z 中读取触觉信息
#       Expert 被迫学会与 z 的接口

这个 masking 策略借鉴了 staged alignment 的思路——先在隔离环境中建立新接口，再放到完整系统中联合训练。

Stage 3：End-to-End Joint Training

解冻什么：除了始终冻结的 DINOv2 触觉编码器骨干，其他全部解冻。
移除 mask：prefix-to-expert 的直接路径恢复，Expert 同时看到 scene + instruction + z。
只用 action objective：Stage 1 的 contrastive + reconstruction loss 不再使用，predictor 仅通过 action gradient 保持 grounding。

注意

为什么三阶段而不是一步到位？Stage 1 固定"z 代表什么"，Stage 2 固定"Expert 怎么用 z"，Stage 3 在两者都已建立的基础上联合优化。Free-latent 变体把三个阶段折叠成一个，但 z 会退化成 prefix 的副本或被绕过——因为没有任何东西阻止 bottleneck 走捷径。

ALTER：从部署数据中离线学习

ALTER（Advantage Labeling from Trajectory Events and Relative Progress）是一套离线 RL 方法，不需要额外的环境交互：

# ALTER 的工作流程
# ================================

# 1. 构建部署语料库
corpus = {
    clean_demos,           # 干净的遥操作示范
    autonomous_rollouts,   # 自主执行（可能有失败）
    HIL_rollouts           # 人在环干预（含恢复轨迹）
}

# 2. 标注 stage progress
#   干净示范 → 触觉接触变化 + 末端运动 + 夹爪状态 + 视觉GEBD
#             → 分段 → VLM 将分段映射到任务模板 → 密集 progress 标签
#   自主/HIL → 触觉检测 object-drop → 稀疏偏好对
#              HIL 日志 → correction intervals → 稀疏偏好对

# 3. 训练 pairwise progress model A_θ(x_a, x_b) ∈ [-1, 1]
#   L = MSE(A_θ, φ(x_a)-φ(x_b))          # 示范对的回归
#     + λ * hinge(m - y*A_θ(x_a, x_b))²  # 事件对的排序

# 4. 冻结 A_θ, 为每条轨迹的每帧打标签
φ̂_t = A_θ(x_t, x_0)    # global progress (vs episode start)
r̂_t = A_θ(x_{t+H}, x_t) # local change (one chunk later)
# → 分配 stage → 在 stage 内按 r̂_t 排序
# → top ρ=30% → "Advantage: positive"
# → bottom 70% → "Advantage: negative"

# 5. 将标签拼接到 task prompt, 继续 flow matching training
#   部署时永远使用 "Advantage: positive"

Duration-Calibrated Stage Progress

一个巧妙的细节：stage progress 按各阶段的平均持续时间加权，而不是等分 [0,1] 区间。这避免了一个短暂的过渡阶段和一个长时间的操作阶段在 progress 空间中占同样大小。

回顾：与 π₀.₅ + RECAP 的对比

在 π₀.₅ 的后续工作 π*₀.₆ (RECAP) 中，Physical Intelligence 同样做了 advantage-conditioned offline RL。ALTER 的主要区别在于：（1）用触觉信号检测 object-drop 事件来提供稀疏偏好对；（2）progress model 的目标按 stage duration 加权；（3）事件对使用 hinge loss 而非简单回归。两者都属于 advantage-conditioned offline RL 的范畴，但 ALTER 更强调利用触觉信号来构建训练信号。

→ 衔接：训练流程理清了。下一节分析关键的设计决策和消融实验——三阶段真的比一步到位好吗？预测式真的比反应式好吗？

Counterfactual Probe：触觉在何时起作用？

Figure 10 是论文中最有说服力的分析之一。在完全相同的观测和采样噪声下，比较有触觉 vs 移除触觉的预测动作轨迹：

— Firm contact（紧密接触）时刻：轨迹分叉，有触觉的路径成功
— Grasp（抓取）时刻：轨迹分叉，有触觉的路径成功
— Free space（自由空间）：两条轨迹完全重合

这直接证明了触觉路径的贡献是选择性的——它只在接触决定结果的时候介入。

最有说服力的任务案例

Socket Plugging（插拔插头）：N₀-VTLA 85% vs π₀.₅ 60%
这是最明显的触觉收益。π₀.₅ 一旦视觉对齐认为插入可行就执行向下运动，如果插头碰到边缘而没进入插槽，它会继续强行推入，最终失败。N₀-VTLA 感知到意外接触后抬臂、重新对齐、重试——把插入从"一次性视觉承诺"变成了"闭环接触感知重试"。

Bottle Standing（立瓶子）：N₀-VTLA 30% vs π₀.₅/ACT 均 0%
操作对象是空的软塑料瓶。π₀.₅ 夹爪关闭过度，将瓶子整个夹起。N₀-VTLA 对夹爪开合做细微连续调整，保持足够接触力控制瓶子但不至于夹起——触觉传感器的形变信号虽然不直接测量力，但与接触力强耦合，成为调节夹持力的实用反馈。

Board Insertion（插板）：N₀-VTLA 25% vs π₀.₅/ACT 均 0%
这个任务两个基线都完全失败，N₀-VTLA 是唯一能完成的模型。

论文的四个核心发现

论文在 Section 6 "Findings" 中总结了四个发现，值得逐一记住：

1. 触觉把插入从"一次性视觉承诺"变成"接触感知重试循环"（Socket Plugging, Board Insertion）

2. 触觉通过夹爪开合调节实现了细粒度力控（Bottle Standing）

3. 触觉精确在"接触决定结果"的时刻改变动作（counterfactual probe）

4. 更强的触觉预训练在 ALTER 下仍保持优势（VTLA+ALTER > VLA+ALTER）

→ 衔接：实验结果确认了触觉的价值。下一节看部署时的具体细节——action chunk 的执行方式和触觉基线重置。
08

部署细节：Action Chunk 执行与触觉基线重置

从训练到部署有几个容易踩的坑。论文在 Appendix D 中明确指出了执行合约。

Full Action-Chunk Execution

论文强调了一个必须遵守的部署合约：必须执行完整个 H=50 步的 action chunk，才能请求下一个 chunk。

注意

为什么不能提前 re-plan？如果只执行 chunk 的前 N 步（N < 50）就重新规划，夹爪关闭命令集中在 chunk 尾部——提前截断会导致机械臂到达目标位置但夹爪永远不闭合。这不是模型的 bug，而是执行时序的问题。模型在完整 chunk 执行下正确关闭夹爪。

触觉基线重置

部署时，每个 episode 开始时发送 reset 消息，清除之前存储的触觉基线。第一帧观测自动成为新的零接触参考。之后该 episode 内所有触觉帧都相对于这个基线做差分。如果某个视角的触觉流不可用，系统 fallback 到"无接触"而不是报错。

推理流程

# 单次推理请求
# 输入: RGB images + tactile views + robot state + language instruction
# 计算: 
#   1. PaliGemma 编码 → prefix
#   2. DINOv2(tac_diff) → g → Predictor → z
#   3. Flow Matching: 10 Euler steps 去噪 → action chunk [50, 32]
# 输出: 50步 action chunk + timing info

# 部署执行:
#   执行完整 50 步 → 请求下一个 chunk → 循环
回顾：与 π₀.₅ 的部署对比

π₀.₅ 同样使用 H=50 的 action chunk 和 10 步 Euler 去噪。N₀-VTLA 在此基础上增加了触觉编码和 predictor 的计算开销，但论文没有给出具体的推理延迟数字。考虑到 DINOv2 是冻结的且 predictor 是轻量级的，额外开销应该相对可控。

不足

论文完全没有报告推理延迟、GPU 显存占用、或具体的硬件型号和设备数量。对于声称"foundation model"的工作，这些部署关键指标的缺失让实际复现困难。Appendix B 也只说了"cluster scale"和"modern accelerators"这样模糊的描述。

→ 衔接：最后一节，退后一步看全局——N₀-VTLA 没解决什么，以及未来的可能方向。
09

局限与反思：开放问题与未来方向

N₀-VTLA 在触觉集成的设计空间中占据了一个有效位置，但距离"通用触觉操作"仍有距离。

论文承认的局限

论文在 Future Work 中提到两个方向：

1. Free-latent 和 supervised 是设计空间中的两个点，中间有更多可能。predictive-latent 的框架值得在当前 predictor 架构之外继续探索。

2. ALTER 需要扩展到更广泛的任务类型来验证其通用性。

更深层的开放问题

不足

触觉传感器的依赖性：N₀-VTLA 使用自研的 visuo-tactile 传感器。虽然冻结 DINOv2 + 可训练投影层理论上支持新传感器接入，但论文没有实际展示跨传感器迁移的效果。如果换成市面上的 DIGIT、GelSight 等传感器，性能是否保持？

不足

数据规模的模糊性：NeoData 的具体规模（episode 数、总时长）没有在本报告中给出，而是推迟到 companion data report [51]。对于"首个大规模触觉预训练"的声明，不给出数据量级让读者难以评估"大规模"到底多大。

不足

灵巧手的缺失：所有实验都在平行夹爪上完成。触觉对灵巧手操作（多指抓取、旋转、滚动）的价值可能更大，但论文完全没有涉及灵巧手场景。

站在更大图景中

N₀-VTLA 的核心贡献不仅是"加了触觉"，而是提出了一种触觉作为预测目标而非观测输入的设计哲学。这种 predictive latent 的思路可以推广：不仅仅是触觉，任何稀疏、事件性的传感信号（力/力矩传感器、声音、温度）都可以用这种"预测而非拼接"的方式集成到 VLA 中。

另一个值得关注的方向是 ALTER 与更通用的 offline RL 方法（如 RECAP）的融合。ALTER 的触觉 event detection 和 duration-calibrated progress 是领域特定的好设计，但它的适用范围目前只验证了三个任务。能否将这些信号自动化、泛化到更广泛的任务集，是一个有趣的研究问题。

总结一句话：N₀-VTLA 证明了"触觉应该被预测而非被感知"这一设计哲学在接触密集操作中的有效性，并通过精心设计的三阶段训练将新的触觉路径安全嫁接到强大的 π₀.₅ backbone 上。ALTER 进一步展示了触觉信号不仅用于在线控制，还能为离线 RL 提供结构化的训练信号。
