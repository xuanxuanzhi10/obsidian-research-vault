01

定位与背景：为什么 VLA 需要触觉？

这节回答：现有 VLA 缺了什么？触觉能补上什么？T-Rex 在这个领域的位置是什么？

想象一下你闭着眼从口袋里摸出钥匙、插进锁孔——你完全靠手指的触感完成了这一系列动作。现有的 VLA 模型（你已经学过的 π0、π0.5、OpenVLA、HyVLA）全部只依赖视觉和语言，它们的「手」是「麻木」的：看得见但摸不到。

这在简单任务（抓取、推动）中问题不大，但遇到接触密集（contact-rich）的任务就会崩溃。比如：翻书页要感觉到纸的薄度、剥鸡蛋不能捏碎、麻将牌面朝下要靠摸来识别花色。这些任务的共同特点是：视觉信息不够，必须通过力和变形反馈来做实时调整。

触觉进 VLA 的三大障碍

T-Rex 系统性地指出了三个阻碍：

障碍一：没有大规模触觉数据。现有的机器人数据集（OXE、DROID、BridgeData）几乎都是平行夹爪+纯视觉，没有同步的触觉信号。从零收集触觉数据又贵又慢——你需要戴数据手套操控灵巧手，每根手指上都有传感器。

障碍二：频率不匹配。VLM 主干网络（如 Qwen-VL）需要处理图像和语言，推理速度约 5Hz。但触觉反应需要 20Hz 以上——你的手指碰到东西要马上调整力度，不能等 200ms 后才反应。这是一个根本性的架构矛盾。

障碍三：触觉信号怎么表示？力信号是高频时序数据（每根手指 6 维力/力矩 × 30Hz），变形是空间图像。直接把原始信号拼接到 token 序列里会淹没有用信息。

T-Rex 的核心思路：不要求触觉数据从预训练阶段就参与，而是设计一个「中间训练（mid-training）」阶段，在已经学会视觉和语言的 VLA 基础上，高效地接入触觉模态。架构上用异步的「快慢系统」解决频率矛盾，用 VQ-VAE 把高频力信号压缩成紧凑的 token。

02

架构拆解：三个 Expert 如何协作

这节回答：T-Rex 的完整数据流是什么？从摄像头/手指到最终动作，信号经过了哪些模块？

回顾：MoT 是什么？

你在学 π0 时接触过 MoT（Mixture-of-Transformers）：同一个 Transformer 主干网络，不同模态使用不同的 FFN 层（即不同的 Expert），但共享同一个 Attention 层。这样不同模态可以互相「看到」对方（通过 shared attention），但各自的表示空间由各自的 FFN 控制。T-Rex 把这个思路从两个 Expert 扩展到了三个。

整体架构：一快两慢

T-Rex 的 MoT 包含三个 Expert，各司其职：

① Latent Expert（潜在专家）——处理头部/腕部摄像头的 RGB 图像和语言指令，通过 ViT 编码视觉特征、Text Encoder 编码语言。它的独特任务是预测未来的视觉表示（future visual latent prediction），为后续的动作规划提供时间锚点。这和你在 π0 里学过的 latent prediction 概念一致。

② Action Expert（动作专家）——低频（~5Hz）动作生成器。接收 Latent Expert 提供的视觉-语言上下文，通过 Flow Matching 从纯噪声去噪成粗略的动作计划。它产出的是一个「半成品」动作——还带有残余噪声。

③ Tactile Expert（触觉专家）——高频（~20Hz）动作精炼器。它不重新处理图像和语言，而是直接复用 Action Expert 的 KV Cache（缓存的视觉-语言上下文），仅基于实时触觉信号对半成品动作做最后的去噪，产出最终可执行的动作。

容易混淆的点

Tactile Expert 并不是一个独立的小网络。它和 Action Expert 共享同一个 Attention 层（shared attention），只是 FFN 不同。关键区别是：Tactile Expert 不需要跑 ViT——它复用缓存好的 KV，所以推理速度可以比 Action Expert 快 4 倍。

完整数据流伪代码

# ===== 输入 =====
rgb_head  = ZED_Mini_camera()         # 头部相机 [640×360]
rgb_wrist = ZED_OneS_cameras(×2)      # 腕部相机 [640×360] ×2
lang      = "Apply toothpaste"        # 语言指令
force     = tactile_force_sensors()   # 10根手指 × 6维力 [10, 6]
deform    = tactile_deform_maps()     # 10根手指 × 变形图 [10, H, W]

# ===== Latent Expert: 编码视觉+语言，预测未来视觉 =====
vis_tokens = ViT(rgb_head, rgb_wrist)           # [N_vis, 2048]
lang_tokens = TextEncoder(lang)                  # [N_lang, 2048]
future_latent = LatentExpert(vis_tokens, lang_tokens)  # 预测未来帧

# ===== Action Expert: 低频去噪（慢流） =====
noise = sample_gaussian(shape=[16, 62])  # 16步动作chunk, 62维动作
x_1 = noise                              # Flow Matching 起点（纯噪声）

# 从 τ=1 去噪到 τ=0.4（6步 Euler），产出半成品动作
x_0.4 = ActionExpert.denoise(
    x_1, steps=6, τ: 1→0.4,
    context=[vis_tokens, lang_tokens]
)
KV_cache = ActionExpert.save_kv_cache()  # 缓存视觉-语言 KV

# ===== Tactile Expert: 高频精炼（快流） =====
tactile_tokens = SpatioTemporalTactileEncoder(force, deform)  # [N_tac, dim]

# 从 τ=0.4 去噪到 τ=0（4步 Euler），产出最终动作
action = TactileExpert.denoise(
    x_0.4, steps=4, τ: 0.4→0,
    context=KV_cache,     # 复用！不重新跑 ViT
    tactile=tactile_tokens # 实时触觉
)
# action: [16, 62] → 16步 × (双臂14关节 + 双手44关节 + 双腕4维SE3)

注意几个关键数字：动作维度 62 = 双臂 14（7×2 关节）+ 双手 44（22×2 手指关节）+ 4（双腕相对 delta）。Action chunk 长度 16，对应 ~3.2 秒的动作规划（5Hz × 16 = 3.2s）。

亮点

Tactile Expert 复用 KV Cache 的设计极其巧妙——它把视觉编码的计算成本完全摊销到了慢流上。快流每次只需要跑 4 步轻量 Euler 积分 + 小 FFN，所以可以在一个 action chunk 内被触发 4 次（偏移 0, 4, 8, 12），实现 ~20Hz 的触觉反应频率。

03

核心技术机制：异步级联 Flow Matching

这节回答：Flow Matching 的去噪过程是怎么被「切成两段」的？为什么能这么切？训练时怎么保证两段的一致性？

回顾：Flow Matching 基础

你在 π0 中学过 Flow Matching：在噪声 x₁ 和目标动作 x₀ 之间画一条直线，模型学习沿这条线的「速度场」。推理时从噪声出发，沿着学到的速度场一步步走到干净动作。与 Diffusion 相比，Flow Matching 的路径是直线插值（而非扩散过程），训练更稳定，推理步数更少。

标准 Flow Matching 回顾

给定一段演示动作 Ademo 和高斯噪声 ε，线性插值为：

# 插值路径
x_τ = (1 - τ) * A_demo + τ * ε    # τ=0: 干净动作, τ=1: 纯噪声

# 恒速目标（两端之差）
v* = ε - A_demo

# 训练损失：让网络预测的速度场匹配 v*
L = E[‖v_θ(x_τ, τ | context) - v*‖²]

注意 T-Rex 的时间方向：τ=1 是纯噪声，τ=0 是干净动作。推理时从 τ=1 往 τ=0 走。

级联切分：在 τ=0.4 处切一刀

T-Rex 的核心创新是把这条去噪路径在 τsplit=0.4 处切成两段：

# ===== 推理时的级联去噪 =====

# 第一段：Action Expert 负责（慢流，~5Hz）
# τ: 1.0 → 0.4，共 6 步 Euler（步长 Δτ = -0.1）
x_1 = ε ~ N(0, I)                           # 起点：纯噪声
for k in range(6):                           # 6 步去噪
    τ = 1.0 - k * 0.1
    v = ActionExpert(x_τ, τ, context=视觉+语言)
    x_{τ-0.1} = x_τ + (-0.1) * v             # Euler 积分

x_0.4 = 结果   # 「半成品」：仍有残余噪声，但已有大致形状
KV_cache = 冻结当前的 KV Cache

# ------- 分割线：以下不再需要 ViT -------

# 第二段：Tactile Expert 负责（快流，~20Hz）
# τ: 0.4 → 0.0，共 4 步 Euler
for k in range(4):
    τ = 0.4 - k * 0.1
    v = TactileExpert(x_τ, τ, KV_cache, 实时触觉)
    x_{τ-0.1} = x_τ + (-0.1) * v

action = x_0   # 最终干净动作 [16, 62]

为什么能切？ 因为 Flow Matching 的速度场 v* 在整条路径上是恒定的（v* = ε - A_demo 不随 τ 变化）。所以不管哪个网络来预测这个速度场，只要它预测得准，最终结果就一样。T-Rex 让两个 Expert 在各自的 τ 区间上分别拟合同一个目标 v*，数学上是自洽的。

异步执行：一个 chunk 内触觉精炼 4 次

这才是真正让触觉「反应式」的关键。一个 action chunk 有 16 步动作。慢流跑一次产出整个 chunk 的半成品。然后快流在 chunk 内的偏移 {0, 4, 8, 12} 处各跑一次，每次用最新的触觉信号来精炼对应的 4 步子 chunk：

# ===== 异步执行时序 =====
# Action Expert（慢流）: ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓ (跑一次，产出16步)
# Tactile Expert（快流）: ████     ████     ████     ████
#                         t=0      t=4      t=8      t=12
#                         用最新   用最新    用最新    用最新
#                         触觉     触觉      触觉     触觉

# 快流每次只跑 4 步 Euler 积分（轻量），耗时短
# → 可以在 action chunk 执行过程中多次更新动作

训练时怎么处理两段？

# ===== 训练损失 =====
τ_act ~ Beta(1.5, 1.0) on (0, 1]      # Action Expert 在整个区间训练
τ_tac = τ_split * τ̃                    # Tactile Expert 只在 [0, 0.4] 训练
  where τ̃ ~ Beta(1.5, 1.0) on (0, 1]

# Action Expert 损失
L_act = ‖f_act(x_τ_act, τ_act; 视觉语言) - v*‖²

# Tactile Expert 损失
# 注意：KV_cache 是 detached 的（不回传梯度）
KV_cache = ActionExpert.forward_detached(x_τ_split)
L_tac = ‖f_tac(x_τ_tac, τ_tac; 触觉, KV_cache) - v*‖²

# 总损失
L = L_act + 1.0 * L_tac + 0.5 * L_future_visual
关键设计细节

Action Expert 在全区间 (0,1] 训练，而不只是 [0.4,1]。 这是为了保持它的独立能力——即使没有 Tactile Expert，Action Expert 自己也能完成完整去噪。这让模型在触觉传感器失效时仍能 fallback 到纯视觉控制。

训练时的延迟增强

部署时快流和慢流是异步的，触觉信号和视觉信号之间天然存在时间差。为了防止训练时过拟合于完美同步，训练时会随机给触觉数据加一个时间偏移 δ ∈ {0, 4, 8, 12}——让触觉特征和视觉特征不完全对齐，模拟部署时的真实情况。

→ 上一节讲了级联 Flow Matching 的机制——慢流出粗动作、快流用触觉精炼。但快流消费的「触觉 token」是怎么从原始传感器信号编码出来的？下一节详解触觉编码器。
04

触觉编码器：把「摸到什么」变成 token

这节回答：机器人手指的原始触觉信号长什么样？如何压缩成 Transformer 能消费的 token？

回顾：为什么需要编码？

前面第 01 节提到过障碍三：原始触觉信号是高频时序+空间图像，直接拼接到 token 序列会淹没信息。这一节就是解决这个问题的。

原始触觉数据长什么样？

每只手有 5 根手指，每根手指的触觉传感器提供两类信号：

1. 力/力矩向量（Force）：每根手指每帧一个 6 维向量（3 维力 + 3 维力矩），采样率 30Hz。T-Rex 用最近 16 帧的力历史 ft-15:t 作为输入，形状为 [16, 6]（每根手指）。

2. 变形深度图（Deformation Map）：单通道的空间图像，记录手指指尖皮肤的变形分布。可以想象成一张热力图——按压一个圆形物体时中间深、边缘浅。这里面包含了视觉看不到的接触几何信息：边缘、滑移方向、剪切模式。

编码方案：三路并行，拼接成 token 序列

# ===== 触觉编码 =====
# 输入：每根手指的力历史和当前变形图

# --- 路径 1: VQ-VAE 编码力的时序模式 ---
# 对每根手指独立处理（权重共享）
f_history = force[t-15:t]                # [16, 6] 每根手指
z_vq = VQ_VAE_Encoder(f_history)         # 1D 时序卷积 → 256维 → 量化
  # 输出：每根手指 1 个离散 token
  # 码本大小 K=64，权重跨5根手指共享
  # 用 finger-identity embedding 区分不同手指

# --- 路径 2: 直接投影当前力 ---
f_current = force[t]                     # [6] 当前帧
z_force = Linear(f_current)              # 保留即时接触信息

# --- 路径 3: 卷积编码变形图 ---
d_current = deform_map[t]                # [1, H, W] 当前变形图
z_deform = DeformEncoder(d_current)      # ResNet-18 前3层 → 展平 → 线性投影
  # 这个编码器是预训练+冻结的（自监督卷积自编码器）

# --- 拼接 ---
z_tactile = concat(z_vq, z_force, z_deform)
# 每根手指产出若干 token，10根手指 → 触觉 token 序列

VQ-VAE 的细节

VQ-VAE（Vector-Quantized Variational Autoencoder）在这里的作用是把 16 帧的连续力信号压缩成一个离散 token。为什么不用 MLP 直接编码？

抗漂移。 触觉传感器存在零点漂移（长时间使用后基线会偏移），VQ-VAE 的量化操作天然具有离散化的鲁棒性——微小的传感器漂移不会改变量化后的码本索引。

信息压缩。 16帧 × 6维 = 96 个浮点数，被压缩成码本中 1 个 256 维向量。这个压缩比很高，迫使编码器只保留最重要的时序模式（比如「力在增大」「检测到滑移」「稳定接触」）。

训练 VQ-VAE 时有一个巧妙的损失设计：magnitude-weighted MSE——力越大的帧权重越高。这是因为大部分时间手指没有接触（力为零），如果不加权，编码器会把精力花在编码「什么都没碰到」这个无意义状态上。

亮点

三路编码各取所长：VQ-VAE 捕捉力的时序动态（最近 16 帧的趋势），直接投影保留即时力值（当前这一帧的精确读数），变形图编码器提取空间接触几何。三者互补，缺一不可——消融实验（第 07 节会讲）证实了这一点。

不足

变形图编码器是预训练后冻结的（frozen），不参与策略训练。这虽然节省参数，但也意味着编码器无法针对具体任务做适应性调整。如果某个任务需要特殊的变形特征（比如布料的褶皱模式），冻结的编码器可能提取不到。

→ 到这里，模型架构的所有组件你都了解了：三个 Expert + 触觉编码器 + 级联 Flow Matching。下一节换个视角，看支撑这个模型的数据是怎么收集和组织的。
05

训练数据：T-Rex Dataset 的设计哲学

这节回答：100 小时的触觉数据是怎么设计的？为什么不按任务收集、而是按「动词-名词组合」？

回顾：数据在 VLA 中的角色

你在 π0.5 中学到了多数据源协同训练的重要性；在 OpenVLA 中学到了 OXE 数据集如何汇聚不同机器人的数据。但这些数据集几乎没有触觉信号，也很少涉及灵巧手。T-Rex Dataset 填补的就是这个空白。

核心设计哲学：动词-名词组合（Verb-Noun Composition）

这是 T-Rex Dataset 最独特的设计决策。传统方法是按最终任务收集数据（如「翻书页 100 次」），但 T-Rex 换了个思路：按动作原语收集。

22 种动作原语包括：close, peel, wrap, fold, wipe, squeeze, insert, extract, press, slide, pick, pour, twist 等。207 种物体涵盖 11 个类别：个人护理、五金工具、玩具、厨房用品、包装胶带、电子产品、布料、衣物、容器、纸张等。

把每种可行的「动词×名词」组合演示 ~16 次，得到的数据集虽然不是任何一个具体任务的专家级数据，但覆盖了接触密集行为的基本词汇表。就像学语言时先掌握基本单词和语法，再组合成句子。

为什么这个设计有效？ 消融实验（第 07 节详述）对比了同样 100 小时的「任务特定数据」和「动词-名词组合数据」——后者在下游任务上泛化更好，零样本迁移能力也更强。原因是动词-名词数据覆盖了更广的接触模式空间，模型学到了可组合的操作「原子能力」。

数据质量控制

收集完成后做了严格的清洗：去掉触觉测量不稳定的、传感器流损坏的、遥操作失误导致异常运动的轨迹。语言标注使用商业 VLM 自动生成（输入头部相机的 4-6 帧抽样 + 物体名和动作名），然后由人工验证去除幻觉和不准确的描述。

亮点

场景多样性做得很好：6 种不同桌面背景，每个场景随机放置 0-5 个干扰物，物体初始位置和朝向也随机化。这让模型不会过拟合到特定场景布局上。

06

训练范式：三阶段渐进式训练

这节回答：T-Rex 的训练分几步？每步用什么数据、训练什么模块、达成什么能力？

回顾：π0 和 π0.5 的训练策略

π0 是「预训练 + 微调」两阶段；π0.5 扩大了预训练数据的异构性，让一个模型同时处理多机器人。T-Rex 在此基础上加了一个中间阶段（mid-training），专门用来注入触觉能力——这个「三段式」是本文的训练创新。

Stage 1: 大规模人类自我中心视频预训练

维度细节
数据22,889 小时人类第一人称视频（来自 EgoScale）
训练模块Latent Expert + Action Expert
Tactile Expert❌ 不参与
学到什么视觉语义理解 + 粗粒度手臂/手部运动先验

这一阶段遵循 EgoScale 的范式：用人类第一人称视频学习「看到什么→做什么」的通用映射。Latent Expert 学习视觉-语言表示，Action Expert 学习从重定向后的人手运动中预测动作。注意：这里完全没有触觉信号——但这没关系，因为这个阶段的目标是获取广泛的视觉运动先验。

Stage 2: 触觉接地的机器人中间训练（Mid-training）

维度细节
数据T-Rex Dataset: 100 小时触觉同步遥操作数据
训练模块Action Expert（适配到机器人观测） + Tactile Expert（从零开始）
学到什么Action Expert 适配到真实机器人动作空间；Tactile Expert 学会用触觉做高频精炼

这是 T-Rex 最核心的训练阶段。人类视频预训练提供了广泛的先验，但它有两个 gap：① 动作空间不同（人手 vs 机器人手）；② 没有触觉信号。Mid-training 用 100 小时的机器人数据同时弥补这两个 gap。

Mid-training 的哲学：不需要在预训练阶段就有触觉数据（那太贵了），而是让模型先通过海量视觉数据学会「如何操作物体」，再通过相对少量的触觉数据学会「如何根据手感微调动作」。就像人先通过视觉学会了抓取的大致策略，然后在实际接触中学会力度控制。

Stage 3: 任务特定的后训练（Post-training）

维度细节
数据每个任务约 100 条演示
训练模块全模型微调
学到什么特定任务的精细技能

值得注意的是，经过 mid-training 后，T-Rex 已经展现出零样本的接触操作能力（pick cube、flip page、press button、wipe plate 等简单任务）。对于更复杂的任务（如开锁、拧灯泡），才需要用 ~100 条任务演示做后训练。

训练超参数

# 训练配置

peak_lr         = 1e-4
lr_schedule     = Cosine → 0
gradient_clip   = 1.0
mixed_precision = bf16
GPUs            = 24 × NVIDIA H100

batch_per_gpu   = 16

亮点

三阶段训练的数据效率非常高。消融实验（Table 3）显示：只有 post-training 没有前两个阶段时平均成功率只有 18%；加上预训练到 45%；加上 mid-training 到 65%。每个阶段都有不可替代的贡献。

去掉异步（w/o Async）：-5%。 同步意味着 Tactile Expert 和 Action Expert 一起跑、一起更新，频率被拉低到 ~5Hz。异步设计让触觉精炼频率达到 ~20Hz，在「分杯」和「抽卡」这类需要快速力反馈的任务上差距明显。

K_slow = 6（τ_split = 0.4）在三个任务上一致最优。K_slow 太小→ Action Expert 去噪不够，交给 Tactile Expert 的半成品太嘈杂；K_slow 太大→留给 Tactile Expert 的去噪空间太小，触觉信息发挥不出来。

实验评估：12 个任务的全面对比

这节回答：T-Rex 在哪些任务上优势最大？什么样的任务最能体现触觉的价值？

硬件平台

Dexmate Vega-1 双臂机器人 + 两只 Sharpa Wave 灵巧手（每只 22 自由度），头部 + 双腕共 3 个 ZED 相机，每根手指 1 个触觉传感器（力/力矩 + 变形图）。遥操作用 Manus 手套（手指动作）+ VIVE Trackers（手腕位姿）。

12 个任务一览

任务被分为三类：力敏感型（翻页、转蛋、擦盘、涂牙膏）、变形敏感型（分杯、麻将分类）、力+变形综合型（开锁、补药、酸碱滴定、抽卡、发牌、拧灯泡）。每个任务 16 次测试，物体位置/朝向随机化，使用累加式评分标准（完成每个子步骤得分）。

关键发现

π0.5 + tactile（6%）比 π0.5（17%）还差！ 这说明简单地把触觉信号拼接到已有 VLA 模型里不仅没用，还有害。原因是预训练时从没见过触觉数据，突然加入一个全新模态会干扰已有的视觉-动作对齐。这恰恰论证了 T-Rex 设计 mid-training 和专门 Tactile Expert 的必要性。

最大优势在哪些任务？

涂牙膏（66% vs 38%）：需要精确控制挤压力度——太轻挤不出来，太重牙膏溢出。纯视觉无法判断挤压力度。

酸碱滴定（76% vs 43%）：需要用吸管吸取液体、滴入烧杯、晃动混合——每个步骤都涉及精细力控。

抽卡（70% vs 41%）：从卡套中只抽出一张卡——需要触觉感知卡的边缘，用拇指和食指的力差来分离单张卡。

最难的任务：拧灯泡（35%）。即使 T-Rex 也只有 35% 成功率（EgoScale 18%）。这个任务需要双手交接灯泡 + 对准螺纹 + 连续旋转，是最长 horizon、最多接触协调的任务。

不足

所有实验都在同一个硬件平台（Dexmate Vega-1）上完成。这意味着我们不知道 T-Rex 的触觉表示方案是否能迁移到其他灵巧手（如 Allegro Hand、Shadow Hand）或其他触觉传感器类型（如 GelSight 视觉触觉 vs 这里用的力/变形传感器）。

09

局限与反思

这节回答：T-Rex 没解决什么问题？如果你要在自己的 HYVLA 框架里集成触觉，应该注意什么？

论文自述的局限

1. 长 horizon 任务仍然困难。 拧灯泡只有 35%，发牌 57%。这些任务需要多步精密接触协调，行为克隆（BC）在这类场景下分布偏移严重。论文建议未来可以引入强化学习或在线交互来改进。

2. 硬件瓶颈。 触觉传感器有零点漂移、标定不一致、且只覆盖指尖没有掌心感应。这些硬件限制直接影响了策略性能的上限。

论文没讨论但值得思考的问题

不足

跨传感器泛化。 VQ-VAE 的码本和变形图编码器都是针对特定传感器（6 维力/力矩 + 单通道变形图）训练的。换一种触觉传感器（如 GelSight 的高分辨率触觉图像、BioTac 的电极阵列），整个触觉编码管线需要重新训练。这是触觉机器人领域的普遍挑战。

不足

推理成本。 论文没有给出具体的推理延迟数字。3.4B 参数的模型在 H100 上跑到 5Hz（慢流）应该不难，但 20Hz 的快流对部署环境有要求。在算力受限的嵌入式平台上，这个架构能否实时运行是个开放问题。

对你预研 HYVLA + 触觉的启示

启示一：不要在预训练阶段加触觉。 T-Rex 最重要的教训是 mid-training 范式——先用纯视觉大规模预训练获取通用先验，再用少量触觉数据做模态对齐。这比从零开始联合训练便宜得多，效果也更好。

启示二：触觉不能简单拼接。 π0.5+tactile 的惨败（6% vs 17%）是最好的警示。触觉需要专门的编码器（VQ-VAE）、专门的 Expert 网络、专门的训练阶段。简单地把力向量 concat 到状态向量里只会帮倒忙。

启示三：频率分离是刚需。 如果你的 HYVLA 架构跑在 ~5Hz，而触觉反应需要 ~20Hz，那你必须设计某种形式的快慢分离——T-Rex 的级联 Flow Matching 是一种方案，其他方案还有 RDP 的 slow-fast diffusion、Fast-in-Slow 的双系统等。核心思路相同：让大模型慢跑出方向，让小模型快跑做调整。

启示四：数据收集策略很重要。 如果你要收集触觉数据做中间训练，参考 T-Rex 的「动词-名词组合」策略而非「任务特定」策略。前者的泛化能力和数据效率都更高。但你需要一个支持触觉的遥操作系统——这是最大的工程门槛。

全文核心要点回顾

数据：100h 触觉同步数据集，按 22 种动作原语 × 207 种物体的组合收集，比任务特定数据泛化更好。

架构：三 Expert MoT（Latent + Action + Tactile），Tactile Expert 复用 KV Cache 实现 4x 频率提升。

训练：三阶段渐进式——人类视频预训练 → 触觉接地中间训练 → 任务特定后训练。

触觉编码：VQ-VAE（力时序）+ 线性投影（即时力）+ 冻结 ResNet（变形图），三路互补。

核心机制：级联 Flow Matching 在 τ=0.4 处切分，慢流 6 步粗动作 + 快流 4 步触觉精炼，异步执行。

结果：12 个任务平均 65%，比最强 baseline（EgoScale 35%）高 30 个百分点。
