01

OpenVLA 在 VLA 家族中的定位——"开源的第一步"

在 RT-2-X 证明"大模型可以做机器人"之后，OpenVLA 要回答的问题是：开源社区能不能复现这件事？

在你已经读过的三篇论文中，HyVLA 用混合 token 架构探索了动作表示的边界，π₀ 用 Flow Matching 和动作专家实现了灵巧操作，π₀.5 用多源异构数据让机器人走进真实家庭。这些工作各有亮点，但它们都面向一个前提性问题——VLM（视觉-语言模型）到底能不能直接变成机器人控制策略？

在 OpenVLA 之前，对这个问题给出肯定答案的是 Google DeepMind 的 RT-2-X——一个 55B 参数的闭源 VLA。RT-2-X 证明了把互联网预训练的 VLM 微调到机器人数据上可以产生强大的泛化策略。但 RT-2-X 有两个致命问题：不开源（无法复现和改进），太大（55B 参数，推理需要多块 TPU）。

OpenVLA 的核心命题

问题：能否用 7B 参数的开源 VLM + 开源机器人数据，构建一个性能超过 55B 闭源模型的通用机器人策略，并且让任何研究者都能在消费级 GPU 上微调和部署？

OpenVLA 的答案是肯定的，但它的方法论出奇简单：不发明新架构，不设计新的动作表示，不引入 Flow Matching 或 Diffusion。它做的事情只有一件——选对底座 VLM，用足够大的数据，做标准的语言模型微调。

回忆前三篇：HyVLA 用了混合离散/连续 token 和 MoT 架构；π₀ 用了 Flow Matching + Action Expert；π₀.5 用了两阶段训练（FAST 预训练→FM 后训练）+ 分层推理。OpenVLA 的方法相比之下极其简单——纯离散化 + 纯自回归，没有任何额外的动作表示组件。这种极简策略到底是优势还是劣势？带着这个问题往下读。

亮点

OpenVLA 是第一个完全开源（模型权重 + 训练代码 + 数据管道）的 7B 级通用机器人策略，托管在 HuggingFace 上，可以用 AutoModel 一行加载。这对 VLA 研究的民主化意义重大。

→ 衔接：OpenVLA 的方法核心是"选对底座 VLM"。那它选了什么，为什么选它？下一节拆解 OpenVLA 的架构——你会发现它几乎就是一个视觉问答模型，只是把"回答"换成了"动作"。
02

架构拆解——从 VLM 到 VLA 只差一步

OpenVLA 的架构不是为机器人设计的——它就是一个视觉问答模型，只是输出变成了动作 token。

上节回顾：OpenVLA 的核心策略是"选对底座 VLM + 标准微调"。现在来看它具体选了什么底座。

OpenVLA 的底座是 Prismatic-7B——一个由 Stanford 研发的开源 VLM。Prismatic 本身是一个视觉问答模型（给它一张图+一个问题，它回答文本），OpenVLA 做的事情是把"回答文本"替换成"回答动作 token"。

三模块架构

# OpenVLA = Prismatic-7B 的三个模块，原封不动继承
#

# │                   OpenVLA (~7B params)                  │
# │                                                         │
# │  ┌──────────┐  ┌──────────┐                             │
# │  │  SigLIP   │  │  DINOv2  │   双视觉编码器 (~600M)      │
# │  │ 语义特征   │  │ 空间特征  │                             │
# │  └────┬─────┘  └────┬─────┘                             │
# │       │              │                                   │
# │       └──────┬───────┘                                   │
# │              │ channel-wise 拼接                          │
# │              ▼                                           │
# │     ┌────────────────┐                                   │
# │     │  MLP Projector  │  2 层 MLP，映射到 LLM 输入空间     │

# │             │ 视觉 token 序列                              │
# │             ▼                                            │
# │     ┌────────────────────────────┐                       │
# │     │      Llama 2 7B            │  语言模型骨干 (~7B)     │

模块一：双视觉编码器（~600M 参数）

这是 OpenVLA 超过其他 VLM 底座的关键。Prismatic 同时使用两个视觉编码器：

SigLIP（400M 参数）：用 Sigmoid Loss 训练的 CLIP 变体。SigLIP 被训练来对齐图像和文本，所以它的特征擅长语义理解——"这是一个杯子"、"那是一盘水果"。但它的空间分辨率较弱（不擅长精确定位物体边缘）。

DINOv2（300M 参数）：自监督视觉编码器。DINO 系列不用文本标注，而是通过图像自身的结构来学习特征。它的特征擅长精细空间信息——物体的边缘、纹理、深度暗示。这对机器人控制至关重要（抓取需要精确知道物体边界在哪里）。

# 双编码器的特征融合
def fuse_visual_features(image):
    # 两个编码器独立处理同一张图
    feat_siglip = siglip_encoder(image)   # [N_patches, D_sig]
    feat_dino   = dinov2_encoder(image)   # [N_patches, D_dino]

    # Channel-wise 拼接（不是相加！）
    # 保留两种特征的独立信息
    feat_fused = concat(feat_siglip, feat_dino, dim=-1)
    # → [N_patches, D_sig + D_dino]

    # MLP 投影到 LLM 的输入维度
    visual_tokens = mlp_projector(feat_fused)
    # → [N_patches, D_llm]
    return visual_tokens

为什么不用单个编码器？论文的消融实验（Appendix D.2）表明，去掉 DINOv2 后性能下降约 5%。虽然降幅不如去掉 OpenX 预训练数据大（30%），但双编码器确实对需要精细空间推理的任务有帮助。SigLIP 知道"那是一个杯子"，DINOv2 知道"杯子的边缘在像素坐标 (203, 415) 附近"——两者结合让抓取更准确。

和前三篇的对比：π₀ 和 π₀.5 用的是 PaliGemma（单编码器 SigLIP），HyVLA 用的也是 SigLIP。OpenVLA 是本系列中唯一使用双视觉编码器的模型，用空间特征弥补语义编码器在定位精度上的不足。但代价是视觉模块更大（~600M vs PaliGemma 的 ~400M）。

模块二：MLP 投影器

一个 2 层 MLP，把拼接后的视觉特征映射到 Llama 2 的输入空间。没有交叉注意力、没有 Q-Former、没有 Perceiver Resampler——就是最简单的线性投影。这意味着 patch 数量原封不动地传入 LLM（224×224 的图像产生 256 个视觉 token），会占据相当长的上下文窗口。

模块三：Llama 2 7B 语言模型骨干

标准的 Llama 2 7B——32 层 Transformer、4096 维隐藏层、32 个注意力头。OpenVLA 没有对 Llama 做任何架构修改（没有加 Action Expert、没有改注意力机制）。它的输入是"视觉 token + 语言指令 token"拼接的序列，输出是下一个 token 的预测。

关键差异

和 π₀ 对比：π₀ 在 PaliGemma 基础上新增了 Action Expert（独立的 MLP 层，用 MoT 和 Block-wise Causal Attention 实现），来生成连续动作向量。OpenVLA 完全不加任何额外模块——它让 LLM 的标准文本解码器直接输出动作 token。这是最大的架构差异。

图像分辨率的选择：224×224

一个让人意外的决定：OpenVLA 只用 224×224 的图像输入。论文实验发现 224 和 384 分辨率在机器人任务上没有性能差异，但 384 的训练时间是 3 倍（因为 patch 数量随分辨率二次增长）。这和 VLM 领域的趋势相反——在视觉问答任务中，更高分辨率通常意味着更好的性能。

局限

224×224 对于精细操作（如拧螺丝、穿线）可能不够。这是一个效率优先的工程妥协，但限制了模型在高精度任务上的天花板。

→ 衔接：架构本身就是一个标准 VLM。但 VLM 输出的是文本 token，而机器人需要连续的关节角度或末端速度。OpenVLA 怎么把连续动作变成 token？下一节看它的动作离散化方案。
03

动作离散化——把连续动作塞进 LLM 的词表里

OpenVLA 把每个动作维度独立离散化成 256 个 bin，然后"借用" Llama 词表中最冷门的 256 个 token 来表示它们。

上节回顾：OpenVLA 的架构是标准 Prismatic-7B VLM，没有任何额外的动作生成模块。这意味着动作必须被表示为 LLM 词表中的 token——所以需要一个离散化方案。

为什么需要离散化？

机器人的动作是连续值——比如"手臂沿 x 轴移动 0.03 米、沿 y 轴移动 -0.01 米、夹爪开合角度 0.85"。但 Llama 2 是一个语言模型，它只能从词表中选择 token 并预测概率分布。你不能让 Llama 直接回归一个浮点数——它的输出层是 softmax over vocabulary，不是 MSE loss。

OpenVLA 的解决方案非常直接：把每个连续维度均匀切成 256 个 bin。

# OpenVLA 的动作离散化流程
def discretize_action(continuous_action, bin_edges):
    """
    continuous_action: [7] → 7个维度 (dx, dy, dz, droll, dpitch, dyaw, gripper)
    bin_edges: 每个维度 256 个均匀间隔的边界值

    输出：7 个离散 token（每个 token 编号 0~255）
    """
    discrete_tokens = []
    for dim in range(7):
        value = continuous_action[dim]
        # 计算边界：用训练数据中该维度的 1st 和 99th 百分位数
        lo = percentile_1st[dim]    # 例如：-0.05
        hi = percentile_99th[dim]   # 例如：+0.05
        # 均匀分 256 个 bin
        bin_index = int((value - lo) / (hi - lo) * 255)
        bin_index = clip(bin_index, 0, 255)
        discrete_tokens.append(bin_index)
    return discrete_tokens  # → [128, 3, 130, 127, 125, 134, 255]

# 每个 token 的精度 = (hi - lo) / 256
# 例如：范围 [-0.05, +0.05] → 每个 bin 宽度 ≈ 0.0004 米 = 0.4 毫米

Token 映射的技巧：借用冷门 token

离散化后，每个 bin 需要一个 Llama 词表中的 token 来表示。OpenVLA 的做法非常巧妙：在 Llama 的 32,000 个 token 中，找到训练数据中使用频率最低的 256 个 token，把它们"征用"为动作 token。

# Token 征用策略
def select_action_tokens(llama_tokenizer, training_corpus):
    # 统计每个 token 在训练数据中的出现频率
    token_freq = count_frequency(llama_tokenizer, training_corpus)

    # 取频率最低的 256 个 token
    least_used = sorted(token_freq, key=lambda t: t.freq)[:256]

    # 这些 token 通常是：
    # - 罕见 Unicode 字符（如 Ħ, ŀ, Ŕ, ǰ）
    # - 几乎不出现的子词片段
    # - 特殊控制字符

    # 建立映射：bin_index → token_id
    action_vocab = {i: least_used[i].id for i in range(256)}
    return action_vocab

# 这样做的好处：
# 1. 不需要扩展词表（词表大小不变，输出层不变）
# 2. 这些冷门 token 原本就没有有用语义，覆盖它们不影响语言能力
# 3. 它们的 embedding 在预训练时几乎没被学习过，可以自由重塑

直觉理解：想象 Llama 的词表是一栋 32,000 个房间的大楼。大部分房间住着常用单词（"the"、"is"、"robot"），但有 256 个房间住着几乎从不露面的租客（罕见的 Unicode 符号）。OpenVLA 把这些租客赶走，让"向左移动 0.03 米"住进去。由于这些房间原本就没人在意，大楼的其他住户（语言能力）几乎不受影响。

为什么是 256 个 bin？

256 = 2⁸，刚好一个字节的表示范围。对于典型的机器人控制信号（末端执行器位移在 ±5cm 范围内），256 bin 的精度约为 0.4mm——对于多数桌面操作任务已经足够。但对于需要亚毫米精度的任务（如 PCB 元件插装），这个精度就显得粗糙了。

每个维度独立离散化的问题

核心局限

维度间的相关性被忽略了。机器人动作的 7 个维度（dx, dy, dz, droll, dpitch, dyaw, gripper）通常是高度耦合的——比如"斜着伸手去拿杯子"需要 dx、dy、dz 同时变化，并且三者之间有特定的比例关系。把每个维度独立离散化，再让 LLM 自回归地逐个预测，模型必须隐式学会这种耦合——这比联合离散化（如 π₀.5 用的 FAST tokenizer）更困难。

和 π₀/π₀.5 的动作表示对比：π₀ 完全不离散化——它用 Flow Matching 直接在连续空间中生成动作块（H=50 步×动作维度），动作间的时间和空间耦合自然保留。π₀.5 在预训练阶段用 FAST tokenizer 离散化，但 FAST 是一个学习到的分词器，它会把多个维度和时间步的联合模式编码成一个 token。OpenVLA 的离散化则是最简单的每维度独立均匀分 bin——没有跨维度建模，也没有时间上的 Action Chunking。
→ 衔接：动作表示方案定了——每步 7 个离散 token。那喂给模型的训练数据从哪里来？下一节看 OpenVLA 怎么从 Open X-Embodiment 的海量数据中筛选出可用的 97 万条。
04

训练数据——97 万条 OXE 数据的筛选哲学

OpenVLA 不是用所有数据训练的，它从 Open X-Embodiment 中精心筛选出 97 万条——筛选的标准揭示了当前 VLA 的能力边界。

上节回顾：OpenVLA 用 7 个离散 token（每维度一个）表示一步动作。这意味着训练数据需要是统一的 7-DoF 末端执行器控制格式。那些格式不一致的数据就需要筛掉——下面看 OpenVLA 的筛选规则。

Open X-Embodiment（OXE）是一个由 Google DeepMind 牵头的大规模机器人数据集联盟，汇集了 20+ 个实验室的数据。但 OXE 中的数据非常异构：有些是双臂、有些是单臂、有些有移动底盘、有些是导航任务。OpenVLA 不能直接用全部数据。

三条筛选规则

# OpenVLA 的数据筛选管道
def filter_oxe_data(all_datasets):
    selected = []
    for dataset in all_datasets:
        # 规则 1：只保留操作任务（去掉导航）
        if dataset.task_type == "navigation":
            continue

        # 规则 2：只保留第三人称摄像头
        if dataset.camera_type != "third_person":
            continue

        # 规则 3：只保留单臂末端执行器控制
        if dataset.control_type not in ["end_effector_delta", "joint_delta"]:
            continue
        if dataset.num_arms > 1:
            continue

        selected.append(dataset)

    return selected  # → 约 970k episodes

为什么只要操作任务？导航任务的动作空间完全不同（线速度+角速度 vs 末端位移+姿态），混在一起训练会让离散化 bin 的含义变得混乱。

为什么只要第三人称视角？这是一个实用的决定——第三人称摄像头能看到更完整的场景，而腕部摄像头的视野太窄。但这意味着 OpenVLA 无法利用腕部相机的近距离细节。

为什么只要单臂？因为动作空间固定为 7 维（6-DoF 末端位姿 + 1 夹爪）。双臂需要 14 维，这和词表映射不兼容。

数据混合权重

筛选后的 25+ 个数据集需要混合在一起训练。OpenVLA 沿用了 Octo 的混合权重策略，主要数据源包括：

DROID 的故事

DROID 数据集一开始以 10% 权重加入训练。但在训练进行到 2/3 时，作者发现模型在 DROID 数据上的动作 token 准确率一直不收敛。他们决定在最后 1/3 的训练中移除 DROID，并把它的权重重新分配给其他数据集。这是一个务实但值得注意的决定——说明并非所有数据都对训练有帮助，数据质量问题在大规模训练中是真实存在的。

数据清洗：去除"全零动作"

论文在附录 C 中揭示了一个重要的数据质量问题：Bridge V2 数据集中，每条演示的第一个 timestep 的动作几乎全是零（因为录制开始时机器人还没动）。如果不清洗，模型会学到"遇到新场景就静止不动"的模式——在部署时表现为机器人冻住（freezing behavior）。

# 数据清洗的关键步骤
def clean_bridge_data(demonstrations):
    for demo in demonstrations:
        # 过滤掉第一个 timestep（通常是全零动作）
        demo.transitions = demo.transitions[1:]
    return demonstrations

# 这个简单的清洗让 Bridge V2 评估上的性能大幅提升
# 注意：RT-2-X 没有做这个清洗，所以它在 Bridge 评估中
# 需要用一个 workaround——查询第二高概率的动作 token
# （因为最高概率的通常是全零）

数据局限

OpenVLA 的 97 万条数据全部是单臂、单摄像头、末端执行器控制。这意味着它无法处理双臂协作、多视角输入、关节空间控制等场景。相比之下，π₀/π₀.5 的训练数据覆盖了多种构型和控制模式——包括 19 维的移动操作机器人和多摄像头输入。OpenVLA 的数据筛选提升了训练的简洁性，但也缩窄了它的能力边界。

→ 衔接：数据准备好了——97 万条统一格式的操作数据。接下来的问题是：怎么训练？OpenVLA 的训练方法会让你惊讶于它的简单。
05

训练范式——标准 Next-Token Prediction 的极简训练

OpenVLA 的训练和 GPT 的训练没有本质区别：预测下一个 token，只是 token 碰巧是动作。

上节回顾：97 万条筛选后的数据，每步动作被离散化为 7 个 token。加上图像 token 和指令 token，每条样本就是一个 token 序列。现在可以用标准语言模型训练了。

训练目标

OpenVLA 的训练目标是标准的交叉熵损失（Cross-Entropy Loss），但只在动作 token 上计算——不对视觉 token 和指令 token 计算损失。

# OpenVLA 的训练流程（伪代码）
def train_step(image, instruction, gt_action):
    # 1. 编码图像 → 视觉 token
    vis_tokens = vision_encoder(image)           # [256]

    # 2. 编码指令 → 语言 token
    lang_tokens = tokenizer(instruction)          # [~20]

    # 3. 离散化真值动作 → 动作 token
    action_tokens = discretize(gt_action)         # [7]

    # 4. 拼接成输入序列
    input_seq = concat(vis_tokens, lang_tokens, action_tokens)
    # → [256 + ~20 + 7] ≈ [283]

    # 5. 自回归预测
    logits = llama(input_seq)

    # 6. 只在动作 token 位置计算交叉熵损失
    loss = cross_entropy(
        logits[action_positions],   # 模型对动作 token 的预测
        action_tokens               # 真值动作 token
    )
    # 语言 token 和视觉 token 的位置不参与 loss 计算

    return loss

为什么只在动作 token 上计算 loss？因为目标是学习"看到图像+指令后做出正确动作"，而不是"复述指令"或"描述图像"。这和 π₀.5 预训练阶段的做法一致——π₀.5 也是只在 FAST 动作 token 上计算 loss。但注意区别：π₀.5 还有 WD（互联网图文）数据会在文本 token 上计算 loss，而 OpenVLA 训练数据中没有任何非机器人数据。

27 个 epoch——为什么 VLA 需要这么多轮？

这是一个令人意外的发现。典型的 LLM 训练只需要 1-2 个 epoch（甚至不到 1 个），因为互联网文本数据量极大。但 OpenVLA 发现机器人数据需要反复学习——从 1 epoch 到 27 epoch，真实机器人评估的性能持续提升。

原因可能是：机器人数据比文本更"模式化"——同一个任务的不同演示在像素级别差异很大（灯光、物体摆放、微小的运动轨迹差异），但需要学习的底层运动模式是相似的。模型需要多次看到同一种模式的不同变体才能抽象出泛化特征。

全参数微调——所有权重都参与

和常见的"冻结视觉编码器"策略不同，OpenVLA 微调所有 7B 参数——包括 SigLIP、DINOv2 和 Llama 2 的全部权重。论文发现微调视觉编码器对 VLA 至关重要，冻结视觉编码器会导致性能急剧下降甚至机器人行为不稳定。

这与 VLM 领域的常识相反。在视觉问答中，冻结视觉编码器通常能更好地保留预训练特征。但 VLA 不同——预训练的视觉编码器没有见过机器人夹爪、操作场景的俯视角、或者物体被遮挡的状态。VLA 任务需要的视觉特征和 ImageNet/互联网数据学到的不同，必须微调才能适应。

训练范式对比：在本系列的四篇论文中，训练范式的复杂度递减——π₀.5 最复杂（两阶段训练 + 多种损失函数），π₀ 次之（Flow Matching 损失），HyVLA 中等（离散+连续混合损失），OpenVLA 最简单（纯交叉熵，单阶段）。OpenVLA 用最少的训练技巧实现了有竞争力的性能，这本身就是一个有价值的发现。
→ 衔接：训练流程清楚了。但"简单"并不意味着"不需要思考"——OpenVLA 在 VLM 底座选择、分辨率、编码器微调等问题上做了大量对比实验。下一节看那些影响最终性能的关键工程决策。
06

设计决策——那些看似简单却关键的工程选择

OpenVLA 的方法论是"在一个简单框架中，用实验找到最好的一组选择"。每个选择都有消融实验支撑。

上节回顾：OpenVLA 的训练是标准 next-token prediction，全参数微调，27 个 epoch。但这些超参数和设计选择不是随便定的——它们是大量对比实验的结果。

决策 1：VLM 底座的选择

OpenVLA 对比了三个 VLM 底座：IDEFICS-1、LLaVA 1.5、Prismatic。在 BridgeData V2 的 5 个语言理解任务上：

IDEFICS-1：在单物体场景中表现尚可，但在多物体场景中无法正确识别目标物体。LLaVA：在多物体语言理解上比 IDEFICS 高 35%，但仍不如 Prismatic。Prismatic：比 LLaVA 进一步提升约 10%，尤其在需要精细空间推理的任务上。

决策逻辑：Prismatic 胜出的原因不是"更大"（它和 LLaVA 参数量相近），而是双视觉编码器（SigLIP+DINOv2）带来的空间推理能力。当场景中有多个物体时，语言指令说"pick up the red bottle"，模型需要先在多个物体中定位红色瓶子——这需要精细的空间-语义对齐，正好是 DINOv2 空间特征的长项。

决策 2：视觉编码器要不要微调？

消融结果（Appendix D.3）非常明确：

策略SigLIP ViT-SOLLaVA v1.5 7B
冻结视觉编码器85% 成功率25% 成功率
微调视觉编码器95% 成功率90% 成功率

冻结 LLaVA 的视觉编码器导致机器人行为完全不稳定。即使是表现更好的 SigLIP，冻结也损失了 10% 成功率。结论：VLA 必须微调视觉编码器。

决策 3：训练多久？

作者用一个代理指标——动作 token 预测准确率——来决定何时停止训练。当准确率超过 95% 时，继续训练的边际收益递减。从 1 epoch 到 27 epoch 的性能曲线显示：前几个 epoch 进步最快，后面逐渐趋平，但直到 27 epoch 仍未完全饱和。

决策 4：学习率

令人意外的简单——固定 2e-5，不需要 warmup，不需要衰减。这个学习率恰好就是 Prismatic VLM 预训练时用的学习率。作者扫描了多个数量级，发现 2e-5 一致最优。这暗示了一个有趣的现象：VLA 微调的最优学习率可能和 VLM 预训练一致，因为两者本质上都是在已有表示上学习新模式。

工程价值

OpenVLA 的每个设计决策都有消融实验支撑，且最终选择都倾向于最简单的方案。这种"选择正确的简单做法"的研究哲学对后续工作非常有指导意义——不是所有问题都需要复杂的解决方案。

→ 衔接：设计决策都做好了，模型训练完了。最关键的问题来了——OpenVLA 到底有多强？下一节看它在真实机器人上的评估结果，以及 7B 模型怎么跟 55B 的 RT-2-X 打。
07

实验评估——7B vs 55B 的真实对决

OpenVLA 在 BridgeData V2 上以 70.6% 成功率超过 RT-2-X 的 50.6%，尽管只有后者 1/7 的参数。

快速回忆架构：OpenVLA = SigLIP+DINOv2 双编码器 → MLP 投影 → Llama 2 7B → 7 个离散动作 token。训练数据 = 97 万条 OXE 单臂操作数据。训练方式 = 标准 cross-entropy，27 epochs。

评估平台与任务

OpenVLA 在两个机器人平台上进行了 "开箱即用"（out-of-the-box）评估，不进行任何额外微调：

BridgeData V2 WidowX：17 个任务，每个 10 次试验 = 170 次评估。涵盖 5 类泛化测试——视觉泛化（未见背景/干扰物）、运动泛化（未见位姿）、物理泛化（未见尺寸形状）、语义泛化（未见物体/指令）、语言理解（多物体中选正确目标）。

Google Robot：12 个任务，每个 5 次 = 60 次评估。分为分布内和分布外（OOD）两组。

为什么 OpenVLA 能超过 RT-2-X？

论文归因于三个因素：

因素一：更大的训练数据——OpenVLA 用了 97 万条轨迹，RT-2-X 只用了约 35 万条（OXE 数据集的子集）。更多数据 = 更多样的操作模式。消融实验（Appendix D.1）表明：去掉 OXE 预训练、只在 BridgeData V2 上训练的 OpenVLA-Bridge 性能下降 30%。

因素二：更好的数据清洗——OpenVLA 过滤掉了 Bridge 数据集中的全零动作 timestep（上文提到的"冻结行为"问题）。RT-2-X 没有做这个清洗，必须用查询第二高概率 token 的 workaround，效果不如直接清洗。

因素三：融合视觉编码器——SigLIP+DINOv2 的组合比 RT-2-X 的单 ViT 编码器提供了更好的空间-语义特征。

公平性提醒

这个比较不完全公平：OpenVLA 用了 RT-2-X 近 3 倍的训练数据，并且做了 RT-2-X 没有做的数据清洗。如果 RT-2-X 也能用清洗后的 97 万条数据重新训练，差距可能会缩小。但由于 RT-2-X 不开源，无法验证。

在哪些任务上 RT-2-X 更强？

语义泛化——在未见过的物体和概念上，RT-2-X（38.8%）略高于 OpenVLA（36.3%）。这不难理解：RT-2-X 的 55B PaLI-X 底座是在更大规模的互联网数据上预训练的，它的语义知识储备更丰富。而 OpenVLA 的 Llama 2 虽然语言能力强，但微调时只接触了机器人数据——没有联合训练互联网数据来保留语义知识。

对比 π₀.5 的数据策略：这恰好印证了 π₀.5 为什么要加入 WD（互联网图文数据）——它通过联合训练来保留并增强模型的开放词汇语义能力。OpenVLA 只用机器人数据微调，虽然操作性能强，但语义泛化能力被 Llama 预训练时的知识"上限"限制住了。

微调到新任务的表现

OpenVLA 还在 Franka-Tabletop（5Hz）和 Franka-DROID（15Hz）上测试了微调效果，每个任务只需 10-150 条演示：

结论是 OpenVLA 在需要语言理解的多指令任务上表现最好（比 Diffusion Policy 和 Octo 都强），但在需要高精度的窄任务（如"把胡萝卜放进碗里"）上不如 Diffusion Policy。这和预期一致——Diffusion Policy 用 action chunking 产生更平滑的轨迹，而 OpenVLA 逐步预测的离散动作在精细操作上更粗糙。

→ 衔接：评估结果说明 OpenVLA 是一个强大的"通用基础策略"。但 7B 模型怎么在实验室外的普通 GPU 上跑？下一节看 OpenVLA 的微调和部署方案——这是它的核心卖点。
08

微调与部署——让 VLA 走进消费级 GPU

LoRA 微调在单块 A100 上 10-15 小时完成，INT4 量化让推理只需 7GB 显存——这是 OpenVLA 对开源社区最重要的贡献。

到目前为止的完整画面：OpenVLA = Prismatic-7B VLM（SigLIP+DINOv2 → MLP → Llama 2 7B），用 97 万条 OXE 数据做标准 cross-entropy 训练 27 epochs，产生的通用策略在 Bridge V2 和 Google Robot 上超过了 55B 的 RT-2-X。现在的问题是：研究者拿到这个模型后，怎么用它？

# LoRA 微调方案
def lora_finetune(base_model, task_data, rank=32):
    """
    LoRA 的核心思想（回忆）：
    原始权重矩阵 W [d_in, d_out] 保持不变
    额外学习两个小矩阵 A [d_in, r] 和 B [r, d_out]
    实际输出 = W·x + A·B·x

    r=32 时，每层额外参数 = 2 × d × r ≈ 2 × 4096 × 32 = 262K
    全模型约 97.6M 额外参数（原始 7B 的 1.4%）
    """
    # 对所有线性层加 LoRA adapter
    model = add_lora(base_model, rank=rank, target="all_linear")

    # 只训练 LoRA 参数，冻结原始权重
    train(model, task_data,
          lr=2e-5,
          epochs="until_convergence",
          trainable_params="lora_only")

    # 训练时间：10-15 小时，单块 A100
    # 对比全参数微调：8块 A100，5-15 小时
    # → LoRA 在单卡上的总 GPU 小时数相当

    return model

核心发现：LoRA rank 不影响性能。论文测试了 r=32 和 r=64，性能几乎相同（68.2% vs 68.2%）。这意味着微调一个新任务只需要约 100M 参数——一个 adapter 只有几百 MB，可以轻松存储和切换多个任务。

量化推理——从 16.8GB 到 7GB

量化是让 OpenVLA 在消费级 GPU 上运行的关键。论文测试了三种精度：

bfloat1671.3%16.8 GB

一个反直觉的结果：INT4 比 INT8 性能更好（71.9% vs 58.1%），而且接近 bfloat16。原因是 INT8 的推理速度反而更慢（量化/反量化操作的开销），在非阻塞控制中导致系统动态变化。INT4 虽然精度更低，但推理更快，保持了与训练数据一致的控制频率。

阻塞 vs 非阻塞控制

在非阻塞控制（non-blocking control）中，机器人在等待模型预测时不会停下来，而是继续执行上一个动作。如果推理变慢（INT8），机器人执行的动作序列的"时间间距"就变了，相当于系统动力学改变了——这会导致性能下降。论文用阻塞控制验证了这一点：当强制所有精度以相同速度运行时，三者性能相当。

推理速度

在各种 GPU 上的推理速度（bfloat16 精度）：

6Hz 对于多数桌面操作任务足够（训练数据中 Bridge 的控制频率是 5Hz），但对于需要 50Hz 的灵巧操作（如 ALOHA 双臂协作）来说太慢了。

远程推理服务器

OpenVLA 还提供了一个远程推理服务器方案：把模型部署在有 GPU 的云端，机器人通过网络流式传输图像并接收动作预测。这样机器人端只需要一个普通电脑+摄像头，不需要本地 GPU。

生态价值

OpenVLA 的代码库直接集成了 HuggingFace 的 AutoModel、LoRA 微调、量化推理——这意味着任何熟悉 HuggingFace 生态的 ML 工程师都可以像微调语言模型一样微调 VLA。这种生态兼容性是 OpenVLA 最大的工程贡献。

09

局限与反思——OpenVLA 没解决什么问题

OpenVLA 证明了"简单方法 + 正确选择"能走很远，但也暴露了纯离散化+自回归范式的天花板。

全文回顾：OpenVLA 用 Prismatic-7B（SigLIP+DINOv2→MLP→Llama 2 7B）作为底座，在 97 万条 OXE 数据上做标准 cross-entropy 训练。动作被离散化为 256 bin 映射到 Llama 的冷门 token 上，每步预测 7 个 token。它以 7B 参数超越了 55B 的 RT-2-X，并且可以用 LoRA 微调 + INT4 量化在消费级 GPU 上运行。

局限一：单图输入，无观测历史

OpenVLA 每步只看一张图像。没有多摄像头输入，没有历史帧堆叠，没有本体感知（关节角度、力矩）。这意味着：

它无法利用时间信息——比如"物体正在滑动"需要对比连续帧才能判断。它也无法做精确的力控制——不知道当前关节受力状态。在需要反应式控制（reactive control）的任务中，这个局限尤为突出。

对比：π₀/π₀.5 使用多摄像头输入（腕部+外部）和本体感知状态；HyVLA 接受多帧历史观测。Diffusion Policy 使用双步观测历史 + 本体感知。OpenVLA 是本系列中输入最少的模型。

局限二：无 Action Chunking

OpenVLA 每步只预测一个时间步的动作（7 个 token = 1 步）。而 Diffusion Policy 一次预测一个动作块（T=8 或 16 步），π₀ 一次预测 H=50 步，π₀.5 一次预测 H=49 步。

# Action Chunking 的优势（OpenVLA 没有）
#
# 无 chunking：       →  →  →  →  →  →  每步独立预测
#                     可能不连贯         推理频率 = 控制频率
#
# 有 chunking (π₀)：  [→→→→→→→→→→→→]    一次预测 50 步
#                     轨迹天然平滑        推理频率 = 控制频率/50
#
# OpenVLA 的问题：
# 1. 轨迹不平滑——每步独立预测，步间可能有抖动
# 2. 推理瓶颈——每步都要跑一次 7B 模型 forward pass
# 3. 无法表达多模态动作分布（同一场景可能有多种合理动作）

核心架构局限

自回归离散 token 无法表达动作的多模态性（multimodality）。在很多操作场景中，同一个状态下有多种合理动作——比如"把物体放到桌上"，放在左边或右边都对。离散化后的自回归模型只能选择一个 bin（mode collapse），而 Flow Matching（π₀）或 Diffusion Policy 天然能表达多模态分布。这也是论文承认 OpenVLA 在"需要灵巧精确的窄任务"上不如 Diffusion Policy 的根本原因。

局限三：控制频率天花板

6Hz 的推理速度对于桌面拾放任务足够，但对于接触丰富的操作（contact-rich manipulation）和高速任务完全不够。ALOHA 双臂系统需要 50Hz，工业装配需要 100Hz+。OpenVLA 的瓶颈在于每步都要做完整的 7B 模型推理——而 Action Chunking 可以通过一次推理覆盖多步，摊薄推理成本。

局限四：无互联网数据联合训练

OpenVLA 只用机器人数据微调，不同时训练互联网图文数据。这导致 Llama 2 的语义知识在微调过程中可能逐渐遗忘（catastrophic forgetting）。实验中语义泛化是 OpenVLA 唯一不如 RT-2-X 的类别，间接印证了这一点。

这就是 π₀.5 的 WD 数据的意义：π₀.5 在训练中保留了互联网图文数据，用它来对抗语义遗忘。OpenVLA 的"只用机器人数据微调"策略更简单，但付出了语义泛化的代价。

局限五：可靠性不足

论文诚实承认：OpenVLA 在测试任务上的成功率通常低于 90%。虽然超过了其他基线，但距离实际部署需要的 >95% 可靠性还有明显差距。对于一个需要连续执行 5-10 分钟的任务来说，每步 85% 的成功率意味着整体成功率可能只有 ~20%。
