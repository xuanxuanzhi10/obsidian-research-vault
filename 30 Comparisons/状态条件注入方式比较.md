# 状态条件注入方式比较：State token 和 AdaRMSNorm 不是二选一

相关概念：[[Adaptive RMSNorm]] · [[Block-wise Causal Attention]] · [[Transformer 参数量估算]]  
论文：[[Hy-Embodied-0.5-VLA]] · [[π₀]] · [[π₀.5]] · [[FTP-1]]

> [!summary] 一句话结论
> “state 如何进入模型”和“flow timestep 如何进入模型”是两个独立设计轴。模型用了 AdaRMSNorm，不代表它一定用 AdaRMSNorm 注入 state，也不代表序列中一定没有 state token。

## 先把两个条件分开

```python
robot_state = [eef_pose, gripper, joints, ...] # 机器人此刻在哪里
flow_time = tau                               # 动作去噪进行到哪一步
```

它们都叫 condition，但语义不同：state 描述物理系统，`τ` 描述生成过程。每一个都可以成为 token、加法 embedding、adaptive norm condition 或 cross-attention K/V。

## 四个模型的真实路径

| 模型 | State 路径 | `τ` 路径 | 是否同时存在 state token + AdaRMS？ |
|---|---|---|---|
| π0 | continuous state 投影成一个 suffix token | 与每个 noisy-action token 拼接后经 MLP | 否；没有 AdaRMS |
| π0.5 | state 序列化为 discrete token，包含在 tokenized prompt/prefix | 经 time MLP 后作为 Action Expert 的 AdaRMS condition | **有 token，也有 AdaRMS，但二者承载不同条件** |
| HyVLA | projected state 构成独立 `[s_t]` block，位于 perception 与 action 之间 | 论文给出 `τ` 作为 flow 输入，但未报告 AdaRMS/AdaLN 注入细节 | 论文只确认 state block，不能声称 AdaRMS |
| FTP-1 | proprioception 经 Fourier encoder + MLP | normalized state feature 与 normalized timestep feature 拼接，共同作为 AdaRMS condition | final design 不把 proprioception 当独立 token |

### π0：state 是 token，timestep 融进 action token

```python
def pi0_suffix(state, noisy_actions, tau):
    state_token = state_proj(state)[:, None, :]          # [B, 1, d]
    action_tokens = action_proj(noisy_actions)            # [B, H, d]
    tau_tokens = repeat(sincos(tau), H)                   # [B, H, d]
    action_tokens = mlp(concat(action_tokens, tau_tokens))
    return concat([state_token, action_tokens]), None     # no AdaRMS cond
```

### π0.5：state 仍是 token，但变成离散 prompt token

```python
def pi05_inputs(observation, noisy_actions, tau):
    # 数据 transform 先把 state 离散化并序列化进 prompt
    prefix = embed([images, language_tokens, discrete_state_tokens])

    action_tokens = action_proj(noisy_actions)            # [B, H, d]
    tau_condition = time_mlp(sincos(tau))                 # [B, d]
    return prefix, action_tokens, tau_condition            # AdaRMS only gets τ
```

这解释了表面矛盾：π0.5 的 `embed_suffix()` 不再添加 continuous state token，但不是“不输入 state”；state 已经由 preprocessing 放进 tokenized prompt。

### HyVLA：state 是有独立因果位置的 block

```python
def hyvla_sequence(perception, state, noisy_action):
    P = vlm_tower(perception)                 # image + language
    S = state_projector(state)                # 独立 state block
    A = action_projector(noisy_action)
    return block_causal_attention([P, S, A])
```

允许的信息流是 `P → S → A`；perception 不看 state/action，state 不看 noisy action，action 读取完整 prefix。这样 state KV 可跨 10 个 Euler steps 缓存。HyVLA 论文没有出现 AdaRMS/AdaLN，因此不能把 π0.5 的实现自动移植到它身上。

### FTP-1：state 与 timestep 共同调制

```python
def ftp1_adarms_condition(state, tau):
    state_feature = layer_norm(state_mlp(fourier_encode(state)))
    time_feature = layer_norm(time_mlp(tau))
    return concat([state_feature, time_feature])
```

FTP-1 恰好证明两种路线可作为消融选项：其官方代码支持 `state_input_mode` 为 `vl_expert`、`action_expert` 或 `adarms`；论文最终选择 AdaRMSNorm，并声称 preliminary experiments 中优于独立 proprioceptive token。

## 为什么不同模型会做不同选择？

| 需要 | Token/block 更自然 | Adaptive norm 更自然 |
|---|---|---|
| 让 action 查询 state 中不同字段 | ✓ 显式注意力交互 | 通道调制较间接 |
| 每层都受同一全局状态影响 | 需要学会读取 | ✓ 直接逐层调制 |
| KV cache | state block 可缓存 | condition 每轮用于调制 |
| 保留离散统一接口 | state 可序列化进 prompt | 需要固定维条件 encoder |
| 不增加序列长度 | 增加 token/block | ✓ 不增加 token |

两者技术上可以共存，而且 π0.5 正是“state token + timestep AdaRMS”的例子。因此不能用“注意力竞争”或“主流趋势”宣布 token 路线已经被淘汰；应由任务、数据接口、cache 和消融决定。

## 研究核查

- **HyVLA 已核对**：Sec. 2.3 明确写 Action Expert consumes `[s_t, A_t^τ]`，并将序列分成 `[I_t,l]`、`[s_t]`、`[a^τ_{t,0:H-1}]` 三块。
- **π0/π0.5 已核对**：OpenPI `Pi0Config` 明确列出两个差异；`embed_suffix` 代码显示 π0 添加 state token、π0.5 用 AdaRMS 注入 timestep。
- **π0.5 边界**：这里核对的是官方 OpenPI 实现；论文级完整机制仍应在正式全文精读时补充页码与实验语境。
- **不要误读**：“state 是 language token”描述的是统一序列接口，并不表示连续本体状态天然是语言；它经过离散化/序列化后占用 prompt token 位置。
