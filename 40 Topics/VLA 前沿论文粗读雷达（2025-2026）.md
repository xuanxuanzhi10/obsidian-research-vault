## 1. Knowledge Insulation：如何接动作专家而不“污染”VLM？

![[90 Attachments/VLA-Paper-Atlas/knowledge-insulation-pipeline.png]]

*Knowledge Insulation Figure 1 · PDF 第 2 页 · 原论文方法图。*

**Pipeline**：VLM backbone 继续接受离散 FAST action-token 与通用 VLM/规划数据的 next-token supervision；连续 Action Expert 从 VLM 表征读取条件并学习 flow action，但其梯度不回流到 VLM。

**它在修什么**：只冻结 VLM 可以保护知识，却可能不给 continuous expert 足够 motor representation；全量 action gradient 回传又可能造成 catastrophic forgetting。KI 用离散动作辅助目标训练 backbone，同时把连续控制梯度隔离。

**最有洞察力的一点**：所谓“知识保护”不是单纯 `requires_grad=False`，而是要同时问：backbone 还学什么目标、expert 从哪里读信息、哪条梯度被切断。它把 representation learning 与 continuous control optimization 分成两条可审计路径。

**证据边界**：这是 π₀.5 之后的独立训练配方，不能倒写成 π₀/π₀.5 初版已经采用。对 HyVLA，最值得做的是检查 FlowPRO/action loss 是否改变 embodied VLM 的 grounding 能力。[原文](https://www.pi.website/download/pi05_KI.pdf)

## 2. Real-Time Chunking（RTC）：把“正在执行的前缀”当成生成约束

![[90 Attachments/VLA-Paper-Atlas/rtc-pipeline.png]]

*RTC Figure 3 · PDF 第 4 页 · 原论文机制图。*

**Pipeline**：机器人执行旧 chunk 的同时生成新 chunk；根据 inference latency 确定哪些动作已经承诺、不能修改；flow/diffusion sampling 固定这段前缀，仅 inpaint 尚未执行的未来部分，使新旧 chunk 连续。

**它在修什么**：普通 action chunking 仍可能在生成期间暂停，或在新 chunk 到达时突然跳变。RTC 不只是 trajectory smoothing，而是把真实 wall-clock 执行进度写进 sampling constraint。

**最有洞察力的一点**：异步控制的状态不是单个 `observation_t`，还包括“哪些未来动作已经下发”。这是一种 commitment state。任何 real-time VLA 若不显式表示它，就可能拿过时状态重写已经发生的过去。

**边界**：RTC 无需重训且适用于 flow/diffusion chunk policy，但它没有创造新感知。如果滑移发生而输入没有触觉，新 chunk 仍只能基于视觉和 state 猜测。[原文，NeurIPS 2025](https://arxiv.org/abs/2506.07339)

## 3. π*₀.6 / RECAP：把失败 rollout 变成 advantage-conditioned 数据

![[90 Attachments/VLA-Paper-Atlas/recap-pipeline.png]]

*RECAP Figure 1 · PDF 第 1 页 · 原论文训练总览图。*

**Pipeline**：从多源示范预训练 VLA；value function 估计成功进度/优势；离线阶段用 advantage conditioning 学会区分更好与更差的行为；部署后收集 autonomous rollout 与 expert intervention，再循环更新策略。

**它在修什么**：BC 只知道“专家做了什么”，不知道相似状态下哪些动作导致失败。RECAP 把 demonstrations、on-policy experience 和 correction 放进统一改进循环，使模型接触自己的状态分布。

**最有洞察力的一点**：失败数据本身不够。若把所有失败轨迹直接当负样本，失败前大量正确动作也会被错误惩罚；必须用 value/advantage 或时间定位回答“从哪个动作开始变坏”。这与 FailureSpot 的 timestamp 问题高度相关。

**边界**：作者展示了复杂真机任务提升，但 reward 定义、人工干预预算和数据筛选共同构成方法成本。不能只比较最终 success 而忽略人类在线参与量。[原文](https://arxiv.org/abs/2511.14759)

## 4. MEM：短期视频记忆与长期文字记忆不该占同一种 token

![[90 Attachments/VLA-Paper-Atlas/mem-pipeline.png]]

*MEM Figure 2 · PDF 第 4 页 · 原论文系统图。*

**Pipeline**：短期最近观测由 spatial-temporal video encoder 压缩，保留遮挡与局部运动；高层 policy 低频写入/更新文字 memory，记录已完成阶段与关键事实；当前 subtask、两类记忆和新观测共同条件化 action expert。

**它在修什么**：把十分钟全部视频帧塞进 VLM，token 和延迟不可接受；只写文字摘要又丢失“刚才手往哪边试过”这类细节。MEM 根据时间尺度选择不同表示。

**最有洞察力的一点**：memory 不是 history 的同义词。history 是原始过去，memory 是**经过选择、压缩、可被未来决策读取的状态**。写入策略和遗忘策略与 encoder 一样重要。

**边界**：文字 memory 可能总结错误并把错误长期传播；短期 video 仍受相机视角限制。触觉事件很适合作为新的低带宽长期事实，例如“该物体已抓稳/刚发生滑移”。[原文](https://arxiv.org/abs/2603.03596)

## 5. π₀.7：用多样 context 把“策略模式”显式放进 prompt

![[90 Attachments/VLA-Paper-Atlas/pi07-pipeline.png]]

*π₀.7 Figure 2 · PDF 第 4 页 · 原论文架构图。*

**Pipeline**：4B VLM、MEM-style video history encoder 与约 860M action expert 组成 5B VLA；除语言指令外，prompt 还可包含 subgoal image、任务表现 metadata 和策略方式信息；多源好坏轨迹在这些 context 下联合训练。

**它在修什么**：混入 suboptimal/autonomous data 时，同一个 observation 可能对应质量完全不同的动作。若不告诉模型“这条数据是什么模式”，条件分布会互相污染。π₀.7 用 context 把数据异质性变成可控制变量。

**最有洞察力的一点**：steerability 不只是自然语言更强，而是把 dataset provenance、quality 和目标风格显式条件化。它近似在回答：同一个 foundation policy 能否根据 prompt 选择专家式、快速式或恢复式行为。

**边界**：context 中提供 subgoal image 或 metadata 会增加信息量，评测时必须区分哪些提示是用户可得、哪些接近 oracle。跨形态 zero-shot 也应单独核查 action mapping 与 calibration。[原文](https://arxiv.org/abs/2604.15483)

## 6. Hy-Embodied-0.5-VLA：把数据、历史、偏好和异步部署连成闭环

![[90 Attachments/HyVLA/hyvla-original-pipeline.png]]

*Hy-Embodied-0.5-VLA Figure 1 · PDF 第 2 页 · 原论文系统图。*

**Pipeline**：定制 UMI 采集高精度 demonstrations；HyVLA-0.5 用 VLM、Compact Memory Encoder、MoT/Action Expert 与 flow matching 生成动作；FlowPRO 从人工偏好 rollout 做后训练；异步部署跨真机和仿真执行。

**为什么值得关注**：很多论文只优化一个模块，HyVLA 强调从 label quality 到 runtime 的整条链。这对真正搭系统有用：模型、数据和 controller 的接口错误会互相放大。

**最有洞察力的一点**：系统收益不能自动归给 MoT。历史压缩减少 POMDP，UMI 提高监督质量，FlowPRO 修决策边界，异步执行减少等待；研究时应逐项拆出贡献。

**边界**：论文报告的 50 Hz 更接近执行/控制频率，不能直接写成大模型每秒重新感知 50 次；完整 latency、action age 和安全回退仍需核查。详见 [[Hy-Embodied-0.5-VLA]]。[原文](https://arxiv.org/abs/2606.14409)

## 7. GR00T N1：System 2 负责语义，System 1 负责连续运动

![[90 Attachments/VLA-Paper-Atlas/groot-n1-pipeline.png]]

*GR00T N1 Figure 2 · PDF 第 3 页 · 原论文总览图。*

**Pipeline**：图像与指令 token 进入 Vision-Language System 2；robot state 经独立 encoder；两者条件化 diffusion Transformer System 1，生成 continuous motor action。训练数据同时包含真机轨迹、human video 与 synthetic data。

**它在修什么**：humanoid action 维度、形态和数据来源更加异构，单一自回归语言 decoder 难以兼顾语义和实时连续动作。dual-system 将 slow semantic understanding 与 fast motor generation 分工。

**最有洞察力的一点**：System 1/System 2 是有用的设计语言，但必须落回计算图：两个模块怎样传信息、是否端到端、动作模块多大、运行频率是多少。否则只是认知科学类比。

**边界**：human/synthetic data 是否真正改善 robot control 要看独立消融；N1、N1.6、N1.7 的 checkpoint、代码与论文版本不能混用。[原文](https://arxiv.org/abs/2503.14734)

## 8. DreamZero：不只预测动作，还让同一模型预测动作后的世界

![[90 Attachments/VLA-Paper-Atlas/dreamzero-pipeline.png]]

*DreamZero Figure 4 · PDF 第 6 页 · 原论文架构图。*

**Pipeline**：video latent 与 action latent 同时加噪，进入共享 autoregressive causal DiT 做 joint flow matching；推理时联合产生 future frames 与 action chunk；真实新观测到达后替换预测历史并更新 KV cache，异步闭环执行。

**它在修什么**：标准 VLA 从当前观测直接回归动作，物理变化只隐式存在于权重中。DreamZero 让未来 world state 成为显式监督，使大量 video-only experience 更容易进入 policy。

**最有洞察力的一点**：WAM 的价值不只是“生成一段好看的未来视频”，而是未来表示与 action 是否**共同建模且能被真实观测纠正**。作者的 7 Hz 系统优化同样是方法成立条件。

**边界**：当前 pipeline 主要联合生成一条未来，不等于对多个候选动作做可靠 counterfactual planning；视频逼真度也不是控制因果准确度。对触觉研究，下一问是未来触觉能否与未来视频/动作一起预测。[原文](https://arxiv.org/abs/2602.15922)

## 9. ReconVLA：用“重建目标区域”逼视觉 token 真正看向操作对象

![[90 Attachments/VLA-Paper-Atlas/reconvla-pipeline.png]]

*ReconVLA Figure 3 · PDF 第 3 页 · 原论文架构图。*

**Pipeline**：视觉/文本进入 VLA；一条 action branch 预测离散动作，另一条 reconstruction branch 从视觉输出条件化 diffusion denoiser，重建 gaze/目标区域；重建 supervision 迫使中间表示聚焦与任务相关的局部信息。

**它在修什么**：VLM 能回答“杯子是什么”，不保证 action token 真正读取了杯口、把手或接触边缘。仅看 attention heatmap 也很难提供训练信号。ReconVLA 用可优化的重建任务建立 implicit grounding。

**最有洞察力的一点**：辅助目标的作用不是生成漂亮图片，而是约束 representation 必须保留 action 所需局部细节。应关注 reconstruction gradient 更新哪些层，以及 gaze region 如何得到。

**边界**：额外 100k trajectories/2M samples 与新 reconstruction head 同时加入时，必须拆分数据收益和机制收益；目标区域标注/裁剪质量也可能成为隐性监督优势。[原文](https://arxiv.org/abs/2508.10333)

## 10. Spatial Forcing：训练时借 3D teacher，部署时仍只看 2D

![[90 Attachments/VLA-Paper-Atlas/spatial-forcing-pipeline.png]]

*Spatial Forcing Figure 1 · PDF 第 1 页 · 原论文方法图。*

**Pipeline**：RGB 和文本正常进入 VLA；训练时冻结的 3D foundation model 从同一场景产生 geometric representation；在 VLA 中间层对视觉 embedding 做 alignment；推理时去掉 3D teacher，仅用原有 2D 输入生成 action。

**它在修什么**：显式 depth/point cloud 需要传感器和跨数据集统一接口，而纯 2D VLM spatial awareness 不足。SF 把 3D 当作训练期 teacher，而非部署期新模态。

**最有洞察力的一点**：这是 geometry distillation，而不是 depth input。成功意味着中间 feature 更易线性读出几何，不意味着模型拥有显式 metrically consistent 3D map。

**边界**：teacher 本身的 bias、配准和训练数据重合会进入 student；测试只看 aggregate success 不足以证明精确 3D 理解，应加 depth probing、viewpoint shift 和遮挡对照。[原文](https://arxiv.org/abs/2510.12276)

## 11. LingBot-VLA：规模化双臂数据、MoT 与可训练工程栈

![[90 Attachments/VLA-Paper-Atlas/lingbot-vla-pipeline.png]]

*LingBot-VLA Figure 1 · PDF 第 2 页 · 原论文总览图。*

**Pipeline**：约 20k 小时、9 类双臂机器人数据被统一 action space；Qwen2.5-VL 类 understanding expert 与 flow-matching action expert 通过 MoT/shared attention 交互；可选 depth distillation 增强空间表征；在 GM-100 与 RoboTwin 等进行 post-training/evaluation。

**为什么值得关注**：它把中国团队的大规模真实双臂数据、开放权重和训练吞吐优化放到一个可下载工程栈中。对于要做二次开发的人，训练代码效率可能比论文榜单更直接。

**最有洞察力的一点**：数据 scaling law 必须与 task/scene/embodiment diversity 一起看；小时数增长若主要来自重复轨迹，物理泛化未必同步增长。

**边界**：原仓库曾把 aggregate throughput 误标成 per-GPU 后更正；因此任何工程数字都要核对单位和版本。GM-100 的开放 split、脚本与机器人配置也应单独审计。[原文](https://arxiv.org/abs/2601.18692)

## 12. LingBot-VLA 2.0：从双臂统一升级为 whole-body action + future distillation

![[90 Attachments/VLA-Paper-Atlas/lingbot-vla2-pipeline.png]]

*LingBot-VLA 2.0 Figure 1 · PDF 第 2 页 · 原论文总览图。*

**Pipeline**：约 50k 小时 robot trajectories 与 10k 小时 egocentric human video 进入重做的数据管线；20 种 embodiment 被映射到扩展 unified action space；MoE action expert 输出 whole-body control；DINO-Video 与 LingBot-Depth 同时提供当前/未来语义和几何 teacher signal。

**它在修什么**：第一版主要覆盖双臂，难以统一移动底盘、腰、头与 dexterous hand。2.0 把 action schema 扩到 whole-body，并把 future prediction 作为 proxy task 注入动态先验。

**最有洞察力的一点**：这里的“预测未来”主要是训练监督/representation distillation，不等于推理时像 DreamZero 一样显式生成并回看未来视频。两者都用未来，但计算图和可用于规划的程度不同。

**边界**：数据量、action space、MoE、教师模型和训练配方同时变化，整体领先不能定位到某一模块；cross-embodiment 仍要看每个目标机器人需要多少 post-training。[原文](https://arxiv.org/abs/2607.06403)

## 13. FailureSpot：失败检测最关键的标签是“从什么时候开始错”

![[90 Attachments/VLA-Paper-Atlas/failurespot-pipeline.png]]

*FailureSpot Figure 1 · PDF 第 1 页 · 原论文问题与方法效果图。论文没有提供一张统一 architecture/pipeline 总览。*

![[90 Attachments/VLA-Paper-Atlas/failurespot-teaching-pipeline.svg]]

*教学示意图（根据论文方法重绘，并非原论文图片）。*

**Pipeline**：从无标签 VLA action chunks 计算相邻 chunk 不一致、冻结/idle、激烈随机运动等 weak signals；用它们训练轻量 detector；再以 active learning 选择最不确定轨迹，少量人工标 timestamp-level failure onset 做精调。

**它在修什么**：trajectory-level 失败标签会把失败前的正常行为也标错，导致告警过早或过晚。FailureSpot 直接把监督粒度对齐到部署真正需要的时间点。

**最有洞察力的一点**：action distribution 自身可以作为 health signal；但它检测的是“策略输出异常”，未必覆盖感知完全自信却选错对象的 semantic failure。

**边界**：检测不等于恢复，更不等于安全保证。真正部署需报告 false positive、检测提前量、触发后 fallback 与额外 latency，而不只 AUROC。[原文，2026-09-03 v1](https://arxiv.org/abs/2609.04277)

## 14. AdaRoboVLG：不要让 foundation model 同时承担物理可行性的一切

![[90 Attachments/VLA-Paper-Atlas/adarobovlg-pipeline.png]]

*AdaRoboVLG Figure 2 · PDF 第 3 页 · 原论文系统图。*

**Pipeline**：base grasp policy 生成跨 hand 的物理可行 grasp candidates，并用 kinematic mapping/force-closure 稳定性评估；foundation models 分别提供 spatial、cognitive、temporal priors；统一 structured grasp interface 组合这些条件，输出适应遮挡、用途和动态物体的抓取。

**它在修什么**：端到端 VLG 若把语义理解、动态跟踪与力闭合全部压进一个网络，扩展新 hand 或新 foundation model 时往往需重训。AdaRoboVLG 把 task-dependent understanding 与 physical grasp synthesis 解耦。

**最有洞察力的一点**：模块化不是旧时代退步。只要接口保留 object geometry、contact 和 hand mapping，foundation prior 更新就能直接改善筛选，而基础 grasp policy 保持可审计。

**边界**：它是 vision-language grasping 邻近路线，不是长时序通用 VLA；候选抓取质量和 force-closure 近似仍限制上限。[原文，2026-09-03 v1](https://arxiv.org/abs/2609.04096)

Google DeepMind 的官方更新强调 reasoning model 与 embodied action model 的产品/系统分工，但当前公开材料不等价于一篇可逐图复核、可下载同权重比较的论文。因此本图鉴不伪造“原论文 pipeline”。值得跟踪的是：reasoning trace 如何转成可执行 subtask、模型与 robot safety/controller 的接口、权重和评测协议是否开放。[官方发布](https://deepmind.google/blog/gemini-robotics-2-brings-whole-body-intelligence-to-robots/)

### Microsoft Rho-alpha

官方项目介绍说明了视觉、语言、动作与触觉的方向，但公开介绍不等于完整训练配方或可复现实验。真正成为论文卡片前，至少需要 architecture、触觉表示、同步频率、loss、数据和真机对照。[[触觉机器人学习全景：感知、表征、闭环与 VLA]] 可继续追踪。[官方介绍](https://www.microsoft.com/en-us/research/story/advancing-ai-for-the-physical-world/)

## 16. 我认为最值得做的四组横向实验

| 研究问题 | 最小对照 | 能排除什么伪结论 |
|---|---|---|
| Future supervision 是否真改善控制？ | 无 teacher / depth teacher / video teacher / joint world-action | 排除只是多了数据或参数 |
| Memory 存什么最有效？ | 等 token 数 raw history / video memory / text event / tactile event | 排除长 context 本身带来的收益 |
| Failure data 怎样使用？ | 丢弃 / 混入 BC / advantage condition / timestamp detector | 排除“数据越多越好” |
| 异步执行怎样影响触觉专家？ | blocking / naive async / RTC / RTC+fresh tactile | 分开 action 接缝与新接触证据 |

## 17. 前沿论文的共同盲点

1. **模块与数据常同时升级**，aggregate result 很难定位因果。
2. **控制频率、model Hz、servo Hz 常被混写**，需要报告 action age 与 jitter。
3. **future prediction 不等于 counterfactual planning**，多数方法只学训练分布下的一条未来。
4. **cross-embodiment 不等于 zero-calibration**，action map、normalization、IK 和 camera 仍在系统中。
5. **failure detection 不等于 recovery**，告警后由谁接管仍是空白。
