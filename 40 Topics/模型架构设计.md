# 模型架构设计

## 架构不是积木清单，而是三组矛盾

### 1. 共享语义 vs 模态专门化

- 完全共享：接口简单，但视觉、语言、动作统计差异大。
- [[Action Expert]] / [[Mixture of Transformers]]：保留 joint context，同时给动作独立参数路径。

### 2. 完整历史 vs token 成本

- 多帧直接拼接：信息直接，但 VLM token 数随帧数增长。
- [[Compact Memory Encoder]]：在视觉编码器内部把历史写入当前帧 token。

### 3. 双向理解 vs 单向条件生成

- 图像内部需要双向建模。
- 动作必须读取 observation，但 observation 不应依赖 noisy action。
- [[Block-wise Causal Attention]] 用 block 内双向、block 间因果来同时满足两者，并为 [[KV Cache]] 创造条件。

### 4. 慢速语义规划 vs 高频接触反馈

- 把触觉直接拼到大 VLA 输入中，可能产生频率错配并干扰已有能力。
- [[T-Rex]] 用 Action Expert 完成 flow 前段、Tactile Expert 完成后段，并复用视觉缓存。
- [[异步触觉动作细化]] 把模态专门化进一步扩展到运行频率和实时调度。

## 阅读任何新 VLA 时的四问

1. 哪些 token 共享 attention？
2. 哪些模态共享 QKV/FFN？
3. action loss 会更新哪些参数？
4. 历史、状态与动作之间的 mask 到底怎样画？
5. 不同传感器频率怎样进入模型，谁负责缓存和更新动作？
