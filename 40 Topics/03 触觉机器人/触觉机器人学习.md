## 1. 触觉到底用来做什么？

不要把“用了触觉”当作一个类别。先判断它在因果链中的角色：

| 角色 | 触觉回答的问题 | 对动作的影响 |
|---|---|---|
| 接触检测 | 碰到了吗、何时碰到？ | 切换 phase / stop |
| 力控制 | 是否过紧/过松？ | 调整抓力、速度、位姿 |
| 滑移检测 | 物体是否开始相对运动？ | 快速增力或重抓 |
| 几何/材质识别 | 接触面是什么形状/纹理？ | 更新状态与策略分支 |
| 插入与约束估计 | 卡在哪个方向？ | 沿约束面搜索/修正 |
| 结果确认 | 页是否翻开、盖是否扣上？ | 终止或重试 |

## 2. 触觉信号怎样表示？

主轴不是模型名字，而是信息结构：

```text
低维：force / torque / pressure statistics
稠密：taxel array / tactile image / deformation depth
动态：history window / vibration / event stream
离散化：VQ code / learned contact vocabulary
跨传感器：统一 token、坐标归一化、sensor adapter
```

当前概念页：[[触觉信号表示]]、[[Morphology-Aware Tactile Token Space]]、[[Latent Tactile Token]]、[[预测触觉与观测触觉]]、[[触觉标点]]。以后每篇论文需记录输入维度、采样率、窗口长度、标定、漂移处理、编码器是否冻结及 token 数量。

## 3. 触觉如何表示在动作里？

严格说，触觉通常不是“写进动作向量”，而是通过以下接口改变动作：

1. **状态条件**：`a_t = π(o_t, tactile_t)`；
2. **动作残差**：`a_t = a_visual + Δa_tactile`；
3. **轨迹/动作块重生成**：依据触觉替换未来 chunk；
4. **生成过程细化**：如 T-Rex 让触觉完成 flow 后半段；
5. **控制目标切换**：位置控制转力控制/阻抗控制；
6. **隐状态更新**：触觉先更新物体或接触 belief，再由 policy 规划。

调研时要明确输出坐标：joint、EEF pose、velocity、torque、gripper/finger joints、impedance 参数，及触觉影响的是哪一部分。

## 4. 怎样融合到当前 VLA 框架？

| 融合方式 | 优点 | 风险 | 适用情形 |
|---|---|---|---|
| Early concat | 实现简单 | 频率错配、干扰预训练权重 | 小模型/同步传感器 |
| Cross-attention | 模态交互清晰 | 每步仍可能重跑大模型 | 中等频率与 token 数 |
| Late fusion / residual | 易保留原 VLA | 修正能力可能受限 | 为现有策略外挂触觉 |
| 独立 Tactile Expert | 参数与职责隔离 | 训练和调度复杂 | 高频触觉、慢 VLA |
| Cache + async | 计算摊销、闭环更快 | 陈旧上下文与并发一致性 | 真机实时部署 |

T-Rex 的 `π₀.5+tactile` 反例提醒我们：拼接式融合可能破坏原能力。需要同时检查参数隔离、注意力方向、训练阶段和部署频率。相关：[[异步触觉动作细化]]、[[Mixture of Transformers]]、[[KV Cache]]。

## 5. 用什么场景验证？

### 好场景应让“视觉-only”存在原则性歧义

- 遮挡下的插入、锁孔/卡槽对齐；
- 外观相同但硬度、摩擦或内部状态不同的物体；
- 易碎、易变形对象的精细抓力；
- 滑移发生后必须在短时间内恢复；
- 翻页、抽卡、分杯等接触结果视觉不易确认的任务；
- 多指接触重分配和双手协同。

### 不只看 task success

记录接触检测延迟、峰值/累计力、物体损伤率、滑移次数与恢复率、动作平滑度、恢复耗时、能耗、deadline miss、跨物体/材质/传感器泛化。

### 必要消融

```text
vision only
+ raw/current force
+ temporal force
+ deformation
+ both force and deformation
synchronous vs asynchronous
matched vs delayed/noisy/calibration-shifted tactile
same objects vs novel objects/materials/sensors
```

## 当前阶段答案（由三篇论文更新）

- **统一 contact token**：FTP-1 的 MTTS 是强基线，但仍依赖人工功能区映射和新 sensor encoder，并非零样本即插即用。
- **预测未来触觉是否值得做**：N0-TWAM 的双路径消融支持“值得”，但不能替代当前观测触觉；先以 auxiliary residual target 做小规模验证更稳妥。
- **fast policy 输出什么**：T-Rex 证明可以直接细化完整 action chunk；是否改为 residual 或 impedance 参数仍需在 HyVLA 控制接口上比较。
- **长任务如何利用触觉**：N0-TWAM 的 [[触觉标点]] 用接触事件切 demonstration 和驱动 scheduler，是可直接复现的工程基线。
- **如何利用部署中的失败与恢复**：N0-VTLA 的 [[ALTER]] 把阶段内相对进步转成文本 advantage；当前只在三个 task-specific 真机任务上验证。
