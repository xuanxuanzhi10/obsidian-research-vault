# 部署与推理优化

## 为什么离线成功率不等于可部署？

真实机器人需要持续输出动作，而大 VLA 推理慢且延迟抖动。部署层必须协调四个时钟：camera、model inference、replanning、servo execution。

| 问题 | 常见机制 | 风险 |
|---|---|---|
| 重复计算固定条件 | [[KV Cache]] | attention 依赖关系不满足时缓存失效 |
| 模型来不及逐步预测 | [[Action Chunking]] | chunk 过时、边界跳变 |
| 新旧轨迹切换 | buffer + trajectory stitching | 平滑不等于安全 |
| 模型太大 | quantization、LoRA adapter | 精度、硬件支持、端到端延迟需实测 |
| EEF 动作落到机器人 | IK / deployment mapper | 不可达、碰撞、奇异位形 |
| 慢视觉与快触觉协作 | [[异步触觉动作细化]] | 视觉缓存陈旧、并发读写错配 |

> [!warning] 三个频率不要混淆
> servo rate 是机器人取动作的速度；replanning rate 是新 action chunk 到达的速度；model forward rate 是模型完成推理的速度。论文只报告其中一个时，不能替它补出另外两个。

## 触觉闭环新增的两个时钟

[[T-Rex]] 还区分慢速 Action Expert（约 5 Hz）、快速 Tactile Expert（约 20 Hz）与 300 Hz 低层控制。快流可复用 [[KV Cache]] 并改写未执行的 [[Action Chunking|action chunk]]，但训练时必须模拟触觉相对冻结视觉缓存的时间偏移。
